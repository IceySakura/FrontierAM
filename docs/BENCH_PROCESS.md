# 评测流程（协议 v6.3）

一道题从接入到出现在榜上，依次经过下面几步。细节规格见 `results/PROTOCOL_V63.md`、`results/EVAL_TIME_LIMITS.md`、`results/BASELINE_POLICY.md`。

## 1. 题目接入

- 出题人提供题面、数据、评测器和参照实现。维护者把它封成一个**题目版本**（`tasks/<题目>/versions/<版本>/`）：锁定镜像、评测器、时限和数据。之后凡是影响评分的改动都出新版本，旧成绩不动。
- 数据分三层：

| 层 | 用途 | 模型能看到吗 |
| --- | --- | --- |
| samples（样例） | 放在开发工作区，供模型理解格式、本地自测 | 能 |
| public（反馈集） | 迭代设置中，模型提交测试后由评测方评测，返回分数和相对参照的比值 | 只看到汇总反馈，看不到用例 |
| private（私有集） | 最终评分 | 不能 |

## 2. 参照标定（本机实测）

- 每道题有两份参照：**0 分锚点**（较弱的参照）和 **50 分锚点**（较强的参照，出题人提供或深度参与，不声称是 SOTA）；**100 分**是题目可达的最好结果（如零误差、全部解出）。
- 两份参照在本机评测槽上、用与模型相同的环境、时限和用例运行，按与候选**完全相同的汇总方式**得到两个锚点值。public 和 private 各标定一次，不混用。历史数字或其他机器的数字不能当锚点。

## 3. 模型尝试

- 每次尝试独占一个开发槽（一个物理核）、断网，工作区只有题面和样例。
- **单轮**：1 小时。结束回合或到时即冻结 `/workspace/submission`，只评一次。
- **迭代**：4 小时。`submit --test` 提交快照到 public 集评测，立即返回、后台进行（同一时刻一个测试，每次最多 15 分钟），报告给出 public 分数和各类别“你 ÷ 参照”的比值；`submit --final` 或到时冻结。
- 榜上记录的过程信息只有两项：迭代的测试提交次数，以及实际用时。

## 4. 私有集评分

- 冻结的源码在评测槽上评分，每个评分任务封顶 1 小时。开发和评测默认全并发（实测真实开发与并行评测只让计时多 0–3%）；每次评分前后各做一次约 0.7 秒的负载小测，比该槽历史最佳慢 25% 以上即报警，单独处理。
- 评测器按题目规则算出每个用例的结果，再按下一节的方式汇总、换算。

## 5. 计分：先汇总，再映射

**所有题目都是先把全部用例的原始指标按题目规则汇总成一个数，再用一次映射换算成 0–100 分**，不是每个用例先换算分数再平均。参照的两个锚点也是在同一批用例上按同样方式汇总出来的，所以映射是“候选的汇总值”对比“参照的汇总值”。

| 题目 | 单个用例的结果 | 汇总成原始指标 | 映射（参照 = 50） |
| --- | --- | --- | --- |
| conic | 是否在时限内正确求解 | 成功率 \(p\) = 解出数 / 650 | \(p \le 0.9\,p_B\) 记 0；到 \(p_B\) 线性升到 50；以上线性到 100 |
| exponential | 本例耗时 ÷ 参照组本例最快成员的耗时 | 比值按母矩阵、结构族、场景、精度逐层等权平均，得 \(R\) | \(100/(1+R)\)；任一用例不合格记 0 |
| galaxy-gravity | 每张快照的相对加速度误差（3 次取平均） | 先在每类星系内平均，再对各类等权平均，得 \(E\) | 对数刻度：弱参照 0，强参照 50，\(10^{-15}\) 为 100；任一调用失败记 0 |
| polarization-demosaicking | 每景四个角度的 RMSE | 对全部场景和角度平均 | 分段线性：弱参照 0，强参照 50，零误差 100；任一场景失败记 0 |
| species-tree | 每例漏掉的分裂数 | 总漏掉数 ÷ 总可能分裂数（批 nRF） | 同上 |
| trajectory-covariance | 每个输入的白化误差（失败按 \(\sqrt d\) 计） | 先在每个（情形，长度）格内平均，再对 30 格等权平均 | 同上 |
| ihvp-sequence | 每步的归一化平方能量误差 | 先对 50 步平均，再对序列平均 | 同上；任一序列失败记 0 |

**为什么先汇总再映射**：
- 映射是非线性的，逐例映射再平均会被“两份参照都解得很好”或“两份都解不出”的用例主导，单例锚点也不稳定。
- 汇总方式沿用出题人原题的定义：各题自己规定哪些用例等权、按什么分组平均。
- exponential 的逐例比值本身就是相对参照的归一化；平均的是比值，最后仍只映射一次。

迭代反馈用同一套汇总和映射，只是数据换成 public 集、锚点换成 public 上的参照值。按类别的分数用该类别内的汇总值计算。

## 6. 失败与“未测”

- **提交导致的失败**按题目规则处理：有的题任一用例失败整份记 0（galaxy、polarization、exponential、ihvp），有的题失败用例按最差值计入平均（conic 记为未解出，trajectory 记 \(\sqrt d\)）。
- **评测设施导致的失败**（平台故障、上游限流中断尝试、测试排队超时等）记为“未测”，不能记 0；受影响的格子重跑，原记录留档。

## 7. 发布与解读

- 每格同时展示原始指标、映射和分数，以及测试提交次数和用时。看板总榜只列每道题最新版本的成绩，旧版本折叠；不同题目版本或协议的成绩不能逐格比较。
- 每道题的“结果解读”说明已有成绩意味着什么：参照是否偏弱、题目或数据是否有缺陷、映射是否合适、模型是否解决不了、超过参照靠工程还是方法创新，并标出需要出题人或人工处理的事项（`results/INSIGHTS.md`）。
- 参照是固定锚点，不因被超过而升级。任一格子 ≥ 80 分或高分段分不开时通知出题人，由出题人决定是否出新版本。
