# 题目名称

时序正定线性系统求解

# 问题描述

隐式微分、连续参数估计和随时间更新的二次模型中，经常需要连续求解一组相关的线性系统。相邻系统的矩阵和右端项可能共同缓慢变化，也可能在某个阶段发生突变。矩阵维度较大，程序通过矩阵与向量乘积查询其作用。

一条实例包含按时间排列的 50 个系统：

$$
H_t x_t^\star=b_t,\qquad t=1,\ldots,50.
$$

每个系统的维度均为 $d=16384$，$b_t\ne0$。矩阵 $H_t$ 对称正定；评测器提供对整条序列均成立的谱界

$$
0<\mu I\preceq H_t\preceq LI.
$$

程序每次只收到当前的 $b_t$、时刻编号、阶段标识和谱界，通过 `hvp(v)` 查询当前的 $H_tv$。返回当前的近似解后，才会收到下一时刻的数据。坐标系在一条序列内保持不变。阶段标识改变时，评测器会通知程序；除此以外不提供未来信息。

数据保留原有的五类序列，并增加包含高维随机创新、全秩系数漂移、特征方向变化和阶段切换的困难序列。矩阵与右端项可以共同变化。相邻系统可以共享有用的信息，但不保证历史近似解、搜索方向或预条件器在下一时刻仍然有效。

# 算法目标

交付同一个可重复运行的 CPU 程序，为每个时刻返回有限向量 $\widehat x_t\in\mathbb R^d$，在时间和内存预算内尽量降低整批平均 loss。

程序可以在一条序列内保留历史解、搜索方向、低秩近似或预条件信息，也可以自行决定各时刻使用多少计算。允许直接法、迭代法及其组合；所有算法遵守相同的信息、时间和内存限制。精度不作为输出有效性的门槛，合法的低精度近似仍按实际 loss 计分。

# 算法约束

每条序列从全新求解进程启动，初始状态为空。程序只可使用当前及此前已提供的数据、合法 HVP 查询结果和随提交固定的通用代码或参数。禁止跨序列保留与评测实例有关的状态，禁止读取评测端私有文件、预存实例答案或利用实例标识查表返回答案。根据查询得到的谱结构、时序特征选择算法是允许的。

运行时使用单进程、一个 CPU 线程，不使用 GPU、网络或外部服务。提供 Python 3、NumPy、SciPy；其他依赖须随源码提供并能离线构建。目标运行环境为 Linux amd64；处理器、镜像、数值库、数据和参照程序版本在本机标定前固定，并与评分锚点绑定。随仓库提供的早期 Apple M3 Max 试验摘要仅供溯源，不作为当前平台的评分锚点。

**整批平均墙钟时间不得超过 30.000 秒/序列，同时每条完整序列最多 30.000 秒。所有序列中的最高求解进程峰值 RSS 不得超过 256 MiB（268,435,456 字节）。** 时间从启动求解进程前计至其正常退出，包含启动、依赖导入、实例预处理、通信、全部 HVP 计算、预条件构建、历史刷新、求解及输出。私有数据装载、参考解构造和独立验分不计时；评测端私有数组和 HVP 提供器工作区不计入提交进程的 RSS。运行更快或使用更少内存不会额外加分。

程序可在整条序列内自行分配时间，不设隐藏的逐时刻等额预算。评测接口会提供序列截止时间，并为进程清理保留短暂余量。两份参照程序内部按剩余时间和剩余时刻数分配计算，这只是参照程序的策略。

HVP 使用 float64 数值计算，不加入随机观测噪声。接口允许一个向量，或最多 64 列向量的批量查询。批量查询每列记录一个 HVP；不设 HVP 次数硬上限。批量计算、验证残差和预处理查询的实际时间均计入预算。参赛程序不直接获得矩阵、生成器的私有参数或参考解。

# 交付要求

在提交目录提供 `solver.py`，实现下列工厂函数：

```python
def make_solver(dimension, seed, options):
    return Solver(...)
```

返回的对象必须实现：

```python
def solve(self, hvp, b, context):
    # 可以通过 self 保留本序列的历史状态。
    # hvp(v) 返回当前 H_t @ v；不允许访问未来的 HVP。
    return x
```

也可返回 `(x, diagnostics)`；诊断信息不参与评分。`b` 和 `x` 的形状为 `(dimension,)`，`x` 必须含恰好 `dimension` 个有限数。评测器对每条序列仅创建一次求解器对象，然后依次调用 `solve`。若使用随机性，应以工厂函数收到的 `seed` 初始化。日志写标准错误。

`context` 提供从 0 开始的 `step`、总步数 `steps`、`mu`、`L`、当前 `phase`、是否变阶段的 `phase_changed` 和单调时钟上的 `deadline`。具体字段、数组与调用契约以 [样例与接口说明](samples/README.md) 及公开自检工具为准。可以随提交包含 C/C++ 扩展及离线构建脚本，但运行期间不得启动额外工作进程或线程。

每次 `solve` 返回后，对应输出即被提交，不能在获得后续系统后修改。程序必须在序列预算内返回全部 50 个向量并正常退出。无需达到指定残差阈值；参照程序使用的残差早停条件只是一项实现选择。

# 评测指标

评测端持有每个系统的参考解 $x_t^\star$。单步 loss 为归一化平方能量误差：

$$
\ell_t=
\frac{(\widehat x_t-x_t^\star)^\mathsf T
H_t(\widehat x_t-x_t^\star)}
{(x_t^\star)^\mathsf T H_t x_t^\star}.
$$

分母严格为正。完全正确的解取 $\ell_t=0$，零向量取 $\ell_t=1$；更差的近似可以超过 1，不进行截断。先对一条序列的 50 个时刻等权平均，再对全部序列等权平均：

$$
E=\frac1N\sum_{i=1}^{N}\frac1{50}\sum_{t=1}^{50}\ell_{i,t}.
$$

本版 public 反馈池和 private 正式集各有 30 条序列：保留原版各 15 条，分别新增五类困难场景与三档谱尺度组合的 15 条。旧数据与新增数据中的每条序列等权，不因来源另行加权。两池采用独立生成参数，不共享具体系统或序列前缀。samples 从 public 中选取少量完整规模样例，另附一个小型接口样例；开发工作区只提供 samples。public 其余数据仅用于迭代反馈，private 只用于最终评分。每条序列调用一次。原始指标 $E$ 越小越好；时间步之间相关，统计单位是整条序列。

**任一序列超时、超内存、违反执行约束、异常退出、缺失输出或返回非法向量，整份提交记 0 分，不进入有效 loss 排名。** 导致验分运算溢出、无法得到有限 loss 的数值输出也不合法。返回全部有限零向量是合法输出，按其实际 loss 计分。评测平台故障由评测方恢复后重跑，不计为提交失败。

零分锚点采用固定的 **冷启动 CG**：每个时刻从零向量开始求解。50 分参照采用本题提供的 **L-BFGS-PCG**：在序列内保留有限历史，刷新当前曲率信息，并用预条件 CG 求解。两份参照必须在目标评测机、相同数据和候选执行环境中重新运行，得到 $E_0>E_{50}>0$；不得把历史或其他机器的数值直接当成本机锚点。

有效提交先汇总整批 loss，再换算一次最终分数；满分 100：

$$
S(E)=
\begin{cases}
0,&E\ge E_0,\\
50\,(E_0-E)/(E_0-E_{50}),&E_{50}\le E<E_0,\\
100-50E/E_{50},&0\le E<E_{50}.
\end{cases}
$$

因此，固定冷启动 CG 对应 0 分，本机标定后的 L-BFGS-PCG 参照对应 50 分，零 loss 对应 100 分。这等价于原题 0–10 分映射乘以 10。更快或更省内存不会额外加分。

样例、public 和 private 不混用评分锚点。缺少正式数据、本机标定、匹配的环境记录，或评测基础设施失败时，结果为“未测”，不给数值分数；不得把这些情况记作选手 0 分。只有已确认由提交导致的非法输出或资源失败才按整份提交 0 分处理。

本版为困难扩展草稿。数据与旧版不同，旧版评分锚点不适用；维护者必须在目标评测机重跑参照并核验区分度后再开放模型尝试。原参照保留用于比较，历史解投影及回收 CG 作为额外验收基线；参照升级须单独确认并冻结。本版不宣称已排除所有可利用的结构。

# 开发材料与数据入口

[样例与本地运行入口](samples/README.md)。材料含一个 4 维、3 步的小型接口样例，以及两个完整规模样例；完整样例的算子不放在工作区，只能通过与正式评测相同的接口（当前右端项与 HVP 查询）运行。小型样例不参与评分，正式实例均为 16384 维、50 步。

小型样例的第一个系统为

$$
H_1=\begin{pmatrix}
4&1&0&0\\1&3&0&0\\0&0&2&1/2\\0&0&1/2&3/2
\end{pmatrix},\qquad
b_1=(1,2,-1,1/2)^\mathsf T.
$$

例如，查询 $v=(1,-1,2,1/2)^\mathsf T$ 返回 $H_1v=(3,-2,17/4,7/4)^\mathsf T$。参考解为

$$
x_1^\star=(1,7,-7,6)^\mathsf T/11.
$$

样例第二步作平滑低秩变化，第三步切换阶段。具体数组和全部参考解见 `samples/smoke.json`；正式求解接口始终只向程序提供当前右端项与 HVP。
