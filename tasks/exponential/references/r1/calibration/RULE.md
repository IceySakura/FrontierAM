# 参照组在 v2 公开集上的标定规则（2026-11-06 修订）

只用公开数据；在任何 agent 提交于 v2 上评测之前冻结。实现：`calibrate_v2.py`，冻结：`scripts/seal/exp2-freeze.py`。

## 第一次标定（2026-11-05，按各成员原规则）为什么一个参数都没选出来

1. **2 个没有可靠参考解的用例被当成了计分用例。** `syn_diffusion2d_p10_k16`、`syn_diffusion2d_b_p10_k16` 的主方法与审计相差容差的 0.031 和 0.029（门槛 0.02），n ≈ 67,000 无法做稠密仲裁，参考解保留全零占位。任何成员在这两个用例上都必然“失败”。
2. **超时被当成了不准。** 原规则要求“所有公开用例都通过”。KIOPS（Octave）在 geometric_b 的 16 请求用例上超过 240 秒上限，expmv 在 diffusion3d 等用例上超时；无论容差设多少，它们都选不出参数。
3. **Expokit 的网格到底了。** 去掉上面两类原因后，容差 0.1·rtol 到 0.001·rtol 已没有失败用例，但最严的 0.001·rtol 最大误差仍为门槛的 0.12，略高于余量 0.1。

## 修订（对所有有参数的成员一致适用）

1. **用例**：只用参考解合格的公开用例。参考解未通过独立验证的用例既不标定也不计分（公开集 66 个计分用例中剔除上述 2 个；`cases/public/manifest.all.json` 保留原清单）。
2. **合格条件**：某个参数值合格，当且仅当没有请求精度不合格，并且它完成的请求中最大误差不超过 0.1 × (atol + rtol·|y_ref|∞)。超时、超 CPU 或超内存是该成员在该用例上的失败：按 DESIGN 第 4 节，它不进入该用例的 virtual best，但不使该参数值不合格。
3. **选择**：容差类成员（Expokit、KIOPS）取“自身及所有更严的值都合格”的最宽松容差，“更严”只检查到倍数 2.2e-4 为止（此时 p10 档的容差为 100 倍双精度机器精度；更严的值求解器只会因舍入出错，不再更准，结果照常记录但不作要求；这条下限只适用于把倍数当作结果绝对容差的成员，ExponentialUtilities.jl 的容差约束的是自适应时间步的每步误差估计，不设下限，网格覆盖 1e-2 到 1e-7）；expmv 每个精度档取合格的最低精度（half < single < double）。
4. **网格扩展**：网格不够时只在公开数据上扩展。Expokit 的网格此前曾因全部合格而向上扩展；这次向下扩展到 1e-6·rtol。KIOPS 新增与 Expokit 相同的容差网格（原为固定 0.01·rtol，在 v2 公开冒烟用例上精度不合格）。
5. **无参数成员**（SciPy、Chebyshev）：只要没有精度不合格就保留；超时同样按第 2 条处理。

计时不参与任何选择，所以各参数值并行评估。

## 待讨论

- 第 2 条使参照组在个别用例上可能只剩少数成员甚至一个成员；若某个计分用例上所有成员都失败，该用例无法计分（评测故障），需在私有集上检查覆盖。
- 剔除没有可靠参考解的用例会使对应母算子少一个精度或场景格子；计分器按现有格子等权平均。
