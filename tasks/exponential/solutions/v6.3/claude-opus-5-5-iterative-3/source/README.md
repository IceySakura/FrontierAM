# Exponential propagation solver (FAMEXP2)

Computes `y = exp(-tL) b0 + t*phi1(-tL) b1` for a sparse symmetric positive semidefinite
matrix `L` over the FAMEXP2 stdin/stdout protocol.  `run.sh` starts the native solver
`expo_v3` (AVX2/FMA build) or `expo_generic`; if neither runs it recompiles `expo_main.c`
into a temporary directory, and as a last resort falls back to the Python reference
implementation `solve.py` (+ `expo.c` kernels).

## Algorithm (expo_main.c)

* **Trivial sessions**: `t = 0` gives `y = b0`; `L = 0` gives `y = b0 + t b1`.
* **Singletons and symmetric pairs** (every row has at most one off-diagonal entry, e.g.
  diagonal or 2x2-coupled operators): closed-form 2x2 eigen-decompositions computed in two
  sequential passes; each request is one `O(n)` pass.
* **Small connected components** (every component of the graph of `L` has at most 64
  nodes, or `n <= 200`): each component is diagonalised densely (closed form for 1x1 and
  2x2 blocks, LAPACK `dsyevd` otherwise).  `exp(-tA)` and `t phi1(-tA)` of every block are
  precomputed, so each request is an exact `O(n s)` transform.
* **General case: Lanczos (Krylov) with two chains.**  One chain approximates
  `exp(-tL) b0`, the other `g(L) b1` with `g(x) = (1 - exp(-t x))/x`; both share a fused
  two-vector SpMV.  After 20 steps the matrix is converted to upper-triangular storage and a
  symmetric SpMV is used (half the matrix traffic); `alpha` and `||w||` are fused into the
  same sweep.  No reorthogonalisation.
  * *Stopping rule*: the Krylov approximation `y_m(s)` satisfies the ODE
    `u' = -Lu + b1` up to a residual `r_m(s) = rho(s) v_{m+1}`, so the error is
    `-int_0^t exp(-(t-s)L) r_m(s) ds`.  We stop when
    `||v_{m+1}||_inf * int_0^t |rho(s)| ds <= 0.5 (atol + rtol * max|y|)`, with `rho`
    evaluated from the tridiagonal eigen-decomposition (composite Gauss-Legendre in `s`,
    geometrically graded towards 0) and `max|y|` bounded from below on a sample of entries.
    This bound tracked the true error within a factor 5-10 in all tests.
  * The tridiagonal problem is solved with an implicit QL iteration that only tracks the
    first and last eigenvector rows; the Krylov coefficients `f(T)e1` are obtained by
    replaying the logged rotations (no dense eigenvector matrix).  Check points are
    scheduled from the observed convergence rate, with a margin proportional to the cost of
    a check.
  * The basis is kept in memory up to 2.0 GB, beyond that the iteration continues with
    three buffers and the tail of the solution is regenerated by a bitwise identical replay.
  * If the estimate stalls at its rounding floor within 20x of the tolerance, the result is
    accepted (independent-rounding runs showed errors of ~0.1 tolerance in that regime).
  * In reuse sessions the previous request's iteration count schedules the checks
    (first at 0.9 m_prev, then m_prev), which removes most intermediate checks.
  * For long runs (`t||L|| >= 1e4`, or `>= 1e3` in reuse sessions) on matrices whose
    stored ordering is scattered (mean |i-j| > 5% of n), a reverse Cuthill-McKee
    reordering improves SpMV locality.
  * *Component split and null-space deflation* (when `t ||L||_inf >= 100`): small
    components (<= 64 nodes) are solved exactly as above and Lanczos runs only on the large
    components.  For large components whose rows sum to zero (graph Laplacians) the
    constant null vector is deflated analytically (`P0 b0 + t P0 b1`).  This removes a
    double-precision accuracy limit of Krylov methods (Ritz values near 0 amplified by
    `g'(0) = -t^2/2`) that otherwise concentrates on tiny components.
* **Shift-and-invert Lanczos (implemented, disabled by default; `EXPO_SI=1`)**: CHOLMOD
  (loaded with `dlopen`, AMD ordering) factorises `L + (10/t) I` once and requests use
  Lanczos on `(L + sigma I)^-1` (12-30 iterations independent of `t||L||`), with a
  validation request against polynomial Lanczos.  It gave 2-5x speedups on stiff 2D
  geometric/mesh reuse sessions in development, but produced one unexplained accuracy
  failure on the public geometric family, so the submitted solver does not use it.
* I/O reads straight into a pre-faulted memory pool (allocated before READY, input
  independent), outputs are written with `write(2)`, and the process ends with `_exit(0)`.

## Dependencies

gcc, system LAPACK/BLAS (`liblapack.so.3`, `libblas.so.3`), optional `libcholmod.so.3`
(SuiteSparse 5.x, used through `dlopen`; the SI path is disabled if it cannot be loaded).
`build.sh` rebuilds all binaries; prebuilt copies are included.

## Public checks

* `python tools/run_local.py --manifest samples/manifest.json --command ./run.sh` passes
  all public samples.
* Development tests (not shipped): dense-eigendecomposition truth on n ~ 2500-6000
  instances of 2D/3D diffusion, geometric graphs (log-uniform weights, many components),
  heavy-tailed networks, signed incidence Laplacians and log-spectrum blocks for
  `t||L|| = 1e-2 ... 1e5` and p4/p7/p10; independent high-degree Chebyshev and tight
  Lanczos references for n up to 120000; shift-and-invert checked against polynomial
  Lanczos in single and 16-request sessions.
