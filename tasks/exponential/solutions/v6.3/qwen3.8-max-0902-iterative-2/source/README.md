# FAMEXP2 — sparse exponential propagation

Computes, for a real symmetric positive semidefinite sparse operator `L` (full
CSR), a time `t` and each of 1 or 16 right hand side pairs `(b0, b1)`:

```
y = exp(-t L) b0 + t*phi1(-t L) b1 ,      phi1(z) = (e^z - 1)/z ,  phi1(0) = 1
```

i.e. the state at `s = t` of `u' = -L u + b1`, `u(0) = b0`.  `L` may be
singular, may have a non-negative diagonal potential, and the right hand sides
may have arbitrary signs.

## Files

| file | role |
|---|---|
| `solver.c` | the solver (single translation unit, POSIX + libm only) |
| `solver_py.py` | pure numpy/scipy fallback, same algorithm, used only if no binary exists |
| `build.sh` | offline build; tries several gcc flag sets and smoke-tests each |
| `smoke.sh`, `smoke.py` | build-time self test (tiny sessions checked against dense `eigh`) |
| `run.sh` | entry point: `exec`s `bin/famexp2`, else the Python fallback |

## Build and run

```sh
sh build.sh        # produces bin/famexp2 (gcc, ~1 s, no network)
./run.sh           # speaks FAMEXP2 on stdin/stdout
```

`build.sh` never fails: it tries `-march=native`, then `x86-64-v3`,
`x86-64-v2`, then plain `-O3`/`-O2`, and after each successful compile it runs
`smoke.sh`, which (a) checks that the binary starts and emits `READY` — this
rejects binaries that die with `SIGILL` on the grading CPU — and (b) runs five
tiny end-to-end sessions (stiff and non-stiff, `one_shot` and a 16-request
`reuse`, a diagonal operator, a zero operator with `nnz = 0`, and `n = 1`) and
compares against `numpy.linalg.eigh`.  If nothing builds, `run.sh` falls back
to `solver_py.py`.

Dependencies: `gcc` (or `cc`/`clang`), `libm`; the fallback needs Python 3,
numpy, scipy.  No network access is required at build or run time.

## Algorithm

Both matrix functions are expanded in Chebyshev series on one interval
`[a, b] = [-R, R*1e-9]` that contains the spectrum of `A = -t L`, and the two
right hand sides of a request are propagated **simultaneously as the two
columns of one block**, so each Chebyshev step costs a single sweep over the
matrix (the dominant cost, `12*nnz` bytes of traffic) instead of two.

With `x = (z - c)/d`, `c = (a+b)/2`, `d = (b-a)/2` and `Â = (A - cI)/d`:

```
V_0 = [b0 | b1],  V_1 = Â V_0,  V_{k+1} = 2 Â V_k - V_{k-1}
y   = sum_k  ( a_k V_k[:,0] + t p_k V_k[:,1] )
```

where `a_k` are the Chebyshev coefficients of `e^z` and `p_k` those of
`phi1(z)` on `[a, b]`.  Everything that touches the whole vector — the sparse
product, the three term recurrence, the series accumulation and the divergence
monitor — is fused into one row loop, so a step performs one pass over the
matrix and a few passes over `O(n)` vectors that stay resident in cache.

**Coefficients.** `a_k` and `p_k` are obtained from the exact Chebyshev–Gauss
interpolation of `e^z` and `phi1(z)`: both functions are sampled at `N` nodes
(`N` the next power of two above `m_cap + 128`, so aliasing from `c_{2N-k}`
lands deep in the super-exponential tail) and transformed with a DCT-II
evaluated as a zero-padded `2N`-point FFT.  The node positions come from
`z_j = b - 2*dd*sin^2(phi_j)`, which avoids the cancellation of
`cc + dd*cos(theta_j)` near `z = 0`; the sines are generated by an angle
addition recurrence in `long double` with an exact restart every 128 nodes, and
`exp` is evaluated only where it does not underflow (elsewhere `exp(z) = 0` and
`phi1(z) = -1/z` to within `1e-26`).  This keeps coefficient setup at a few
tens of microseconds, which matters because on small operators it would
otherwise rival the solve itself.

**Degree.** `m = ceil(C(p) * sqrt(R)) + K(p)` with `C = 3.45, 4.25, 5.05` and
`K = 12, 16, 22` for `p4, p7, p10`.  These constants were calibrated against
extended-precision (`long double`) Chebyshev references on mesh and geometric
graph operators at `R` up to `1e5`; they leave the observed infinity-norm error
at roughly 1% of the acceptance threshold.  A safety extension then adds steps
(after `m`, up to `1.3 m`) if the last term is still above `2%` of
`atol + rtol*max|y|`, which covers the case where `max|y|` turns out to be much
smaller than `||b||`.

**Ordering.** When the incoming numbering is non-local (`sum |row-col|` over all
non-zeros exceeds `n*nnz/16`) and the planned degree is at least 100, a reverse
Cuthill-McKee permutation is built (min-degree pseudo-peripheral root, BFS with
degree-sorted neighbour queues, reversed) and the operator is rebuilt in that
order; the permutation is kept only if the profile drops below 70% of the
original.  Right hand sides are gathered and results scattered through the same
permutation, so this is invisible outside the sparse product.  On randomly
ordered geometric graphs this reduces the sweep cost by ~1.6x because the
`x[j]` gathers stop missing cache.

**Spectral interval.** `R = t*||L||_inf` is always a rigorous bound
(`lambda_max <= ||L||_inf` for symmetric `L`) and is computed in the same pass
that scans the CSR data.  When the planned degree is large enough to pay for it
(`m >= 24` for `reuse`, `m >= 200` for `one_shot`), a short Lanczos run
(36 steps, no reorthogonalisation, `O(n)` memory) gives the largest Ritz value,
which is a rigorous *lower* bound on `lambda_max`.  The run stops after 12 steps
if that bound already reaches `0.97*||L||_inf`, since no worthwhile tightening is
left; otherwise `R = 1.01 * t * lambda_max^est` is used when it is smaller.  This removes the up-to-`2x` slack of the
`||L||_inf` bound on irregular graph operators (`lambda_max ~ d_max + 2 sqrt(d_max)`
versus `||L||_inf = 2 d_max`), cutting the degree by up to 25%.

**Divergence guard.** Chebyshev only diverges if the interval fails to contain
the spectrum, and then `||T_k(Â) b||` grows exponentially.  Because
`||T_k(Â) b||_2 <= ||b||_2` whenever the spectrum is inside `[-1, 1]`, the step
kernel also returns `max|V_k|` and the request is restarted with the rigorous
`R = t*||L||_inf` as soon as it exceeds `1.5 * max(||b0||_2, ||b1||_2)`.  The
guard is free: the reduction is fused into the step that already writes `V_k`.

**Special cases.** `t = 0` returns `b0`; `R = 0` (zero operator) returns
`b0 + t b1`; a purely diagonal operator is detected during the structural scan
and handled elementwise with `exp`/`phi1` (no iteration at all).

**Interface.** `READY\n` is written before any input is read; the header, CSR
arrays and each request are read with a single `read()` loop per block directly
into the final buffers (the `uint64` `indptr` is narrowed to `uint32` once);
each answer is written with one `write()` of exactly `8n` bytes.  Only protocol
bytes go to stdout, diagnostics to stderr (enabled with `FAMEXP2_VERBOSE=1`).
Non-finite results are replaced by `0.0` before writing so that a malformed
case can never emit `NaN`.

## Cost and resources

Per Chebyshev step: one sweep over the matrix (`12` bytes per non-zero) plus
`O(n)` vector traffic; memory is `~ 12*nnz + 30n` bytes (well under 4 GiB at
the size limits), and three `2n` work vectors stay cache resident.  Measured on
one AMD EPYC core (development host, shared cache):

| case | n | nnz | requests | time |
|---|---|---|---|---|
| mesh, `t*||L||_inf = 1e5`, p10 | 120000 | 598600 | 1 | 1.17 s |
| mesh, `t*||L||_inf = 1e5`, p10 | 120000 | 598600 | 16 | ~18 s |
| geometric graph, `1e5`, p10 | 100000 | 914924 | 1 | 1.45 s |
| mesh, `1e3`, p7 | 120000 | 598600 | 1 | 0.12 s |
| mesh, `1e-2`, p10 | 120000 | 598600 | 1 | 0.03 s |

A sweep moves `12` bytes per non-zero, so the hard cases run at roughly the
single-core memory bandwidth limit; measured throughput is ~1.3 ns per non-zero
on both banded and reordered unstructured operators.

Process start-up is ~1 ms, so short sessions are dominated by input transfer
rather than by the interpreter or library initialisation.

## Public checks

```sh
python task/tools/run_local.py --manifest task/samples/manifest.json \
       --command "/workspace/submission/run.sh" --repeats 3 --output dev_report.json
```

All six sample cases (five synthetic structure families plus the analytic
diagonal control) pass all three repeats, and `build.sh`'s `smoke.py` re-checks
five tiny sessions against dense `eigh` every time the binary is compiled.
Accuracy was additionally validated
on generated operators — 5-point meshes and `k`-nearest-neighbour geometric
graphs, `n` from 625 to 120000, `t*||L||_inf` from `1e-2` to `1e5`, all three
precision levels — against `long double` Chebyshev references computed
independently of the solver; the observed infinity-norm error stays below 2% of
the acceptance threshold in every case.
