# 参照（baseline）原则（用户确定；11-11 修订）

参照是出题人（人类研究者）自己实现或深度参与的一版，记 50 分，是计分的锚点，**不声称是 SOTA**。模型超过参照就照常记分；参照是否够强、要不要改，由出题人判断，我们不自行升级参照。做法与 AlgoTune（常用库为参照，加速比不封顶）、RE-Bench（作者参照记 1，可超过）、FrontierCO（已知最优解为锚点，被超过也不改）一致：锚点固定，分数不依赖“超出的原因”。

1. **参照来源。** 出题人提供的参照，或出题人深度参与设计与审定的参照（如 exponential-v2 的 7 方法参照组）。不用被评模型的提交，也不用由 agent 按模型解法挑选技术写成的实现。agent 独立写的其他人类方法实现只作参考材料，不作锚点。
2. **先冻结、后开放。** 参照的参数只用公开数据确定，冻结后才开始模型尝试；参照最好是固定配置（不随机器速度自适应），锚点可复现。
3. **发布前检查计分。** 跨数量级的指标用对数换算；参照耗时离时限至少留 25% 余量；不满足时记为待反馈出题人的事项。
4. **分数过高时请出题人来看。** 触发条件：任一格子 ≥ 80 分，或多个模型挤在高分段分不开。触发后通知出题人（附各格原始指标与模型做法），由出题人决定是否出新版本、如何修改参照；我们不自行修改。
5. **参照分版本，不追溯改分。** 每个成绩注明对应的参照版本；旧成绩保持不变；不同参照版本的成绩不混排。
6. **超过参照的格子：只记做法。** 在 `BASELINE_REVIEW.md` 写一段做法说明（技术与能查到的人类出处）。不判断“调参还是创新”，不标“待复核”，不卡发布。

## 修订记录

- 11-10：参照按本机实测选“最强人类 SOTA”；每个超过 50 的格子做消融，判断“调参还是创新”，调参则把 insight 并入参照。
- 11-11：用户质疑“超出参照就考虑整合进参照”是否合理，并确定：参照就是人类研究者自己做的或深度参与的一版，不认为它是 SOTA；分数太高时由出题人来改参照。区分“工程还是创新”很难，并入模型做法会让标尺随模型漂移、历史成绩不可比，用被评模型的解法当参照是循环论证。据此：galaxy-gravity-v3 的参照用出题方的 Treecode2（r1）（曾短暂换为 opus 解法 r2、按论文写的 FMM r3，均撤下）；exponential-v3 用原 7 方法参照组（Chebyshev 第二版不并入）。
