# 参照（baseline）原则（用户确定；11-27 修订）

参照记 50 分，是计分的锚点。参照取**本题数据与资源约束下能做到的最强人类实现**：人类方法（有文献或公开代码出处）的实现，参数在本题公开数据上重新调过。原作代码不是针对本题的新问题、新数据调的，在本题数据上调参仍是合理的人类参照。参照不声称是绝对 SOTA，模型超过参照照常记分。做法与 AlgoTune（常用库为参照，加速比不封顶）、RE-Bench（作者参照记 1，可超过）、FrontierCO（已知最优解为锚点）一致：锚点固定后，分数不依赖“超出的原因”。

1. **参照来源。** 出题人或已发表的人类代码，或 agent 按人类文献独立编写的实现。只用有人类出处的技术（逐项注明文献）；不用被评模型的提交，也不用从模型解法中学到的技术（例如 galaxy 的核拆分）；编写者不接触模型提交。
2. **只用公开数据调参，规则事先写定。** 参数只在公开数据（样例与反馈集）上确定；候选空间、资源约束与选择目标在扫描前写入参照目录。冻结后在私有集上用正式评测器标定。配置固定：可以依赖接口给出的输入（如规模、逐例时限），不随机器速度自适应，锚点可复现。
3. **资源与计分检查。** 参照耗时离时限至少留 25% 余量（不超过时限的 0.8 倍），内存在评测上限内；跨数量级的指标用对数换算。时限原本按旧参照标定的，换参照时时限不变，比较的是同样资源下的精度。
4. **分数过高时先查参照。** 任一格子 ≥ 80 分，或多个模型挤在高分段分不开时，先查有没有更强的人类实现（包括在本题数据上调参），有则按本原则更新参照；仍然很高就照常记分。
5. **参照分版本。** 每个成绩注明参照版本。更新参照时，该题该版本的所有格子按新锚点重算（原始指标不变，只重算分数），旧锚点与旧分数留档。
6. **超过参照的格子：只记做法。** 在 `BASELINE_REVIEW.md` 写一段做法说明（技术与能查到的人类出处），不卡发布。

## 修订记录

- 11-10：参照按本机实测选“最强人类 SOTA”；每个超过 50 的格子做消融，判断“调参还是创新”，调参则把 insight 并入参照。
- 11-11：用户质疑“超出参照就考虑整合进参照”是否合理，并确定：参照就是人类研究者自己做的或深度参与的一版，不认为它是 SOTA；分数太高时由出题人来改参照。区分“工程还是创新”很难，并入模型做法会让标尺随模型漂移、历史成绩不可比，用被评模型的解法当参照是循环论证。据此：galaxy-gravity-v3 的参照用出题方的 Treecode2（r1）（曾短暂换为 opus 解法 r2、按论文写的 FMM r3，均撤下）；exponential-v3 用原 7 方法参照组（Chebyshev 第二版不并入）。
- 11-27：用户确定参照取“本题数据上调过参的最强人类实现”，agent 按人类文献独立编写的实现可以作锚点，所有题目按此原则；更新参照时该题全部格子按新锚点重算。仍不用模型解法及其中的技术，以免循环论证。起因：galaxy-gravity v4 的 50 分点（Treecode2 改进树，θ=0.7）在同样 CPU 下调参最多把误差降到 0.74 倍（`scripts/analyze/galaxy-treecode-tuning.py`），而人类的主流方法高阶笛卡尔 FMM（Dehnen 2014）强得多；用户认为在新数据上调参仍是合理的人类参照。
