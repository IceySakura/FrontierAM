# FrontierAM 排行榜（本 x86_64 服务器，协议 v6，2026-11-04/05）

每个模型、每道题只有一次开发尝试：独占一个开发 slot（一个物理核），2 小时，工具环境断网，结束即冻结。只有冻结后的源码进入评测，并与在本机重跑的参考实现比较。证据在 `store*/`，方法细节见 `CONIC_FULL.md` 和 `CONCURRENCY.md`。

## 协议 v6

- 模型流量走 agent-traffic-runtime（ATR）。每个模型使用自己的原生 harness，推理强度、输出长度和上下文都设为 ATR 目录中验证过的最高值。
- harness 运行在断网的开发容器内，通过 Unix socket 连到宿主上的 `atr serve`。凭据只留在宿主，不进入容器。
- 开发容器以 UID 2000 运行。原因是 RLIMIT_NPROC 按 UID 在整台主机统计，评测器的进程上限会和开发 harness 的线程互相干扰（`CONCURRENCY.md` §5）。
- 客户端超时覆盖整个开发窗口：ATR 的非流式传输在长回答生成完之前不发送任何数据，原来的短超时会误判为失败。

## 锥优化（650 例全集，主榜）

参考为 Clarabel 0.11.1，已在本机全集上重跑。数字是三次重复都在时限内通过独立检查的实例数。"原时限"是题目包冻结的、按原机器标定的时限；"重标定"是用同一规则、按本机参考运行重新标定的时限。

| 模型（v6） | 原时限 | 本机重标定 | 得分（满分 100，按本机重标定） | 时限 > 1 秒的 228 例（原时限 / 重标定） |
| --- | --- | --- | --- | --- |
| 参考（Clarabel 0.11.1） | 447（0.688） | 513（0.789） | 50 | 36 / 93 |
| gpt-6.1-sol | **464（0.714）** | 467（0.718） | **5.2** | **130 / 132** |
| gpt-6-astra | 397（0.611） | 404（0.622） | 0 | 74 / 81 |
| hy4 | 336（0.517） | 339（0.522） | 0 | 60 / 61 |
| claude-opus-5-5 | 329（0.506） | 334（0.514） | 0 | 36 / 40 |
| step-5-preview | 0（2 小时内无有效提交） | — | 0 | — |

得分按题目的映射计算：与参考持平得 50 分，解出数不超过参考的 90% 得 0 分，全部解出得 100 分。要点（详见 `CONIC_FULL.md`）：

- **整体成功率**：在重标定时限下（题目的设计口径），没有模型超过参考。gpt-6.1-sol 最接近，但显著落后（p = 0.0048）。原时限下 sol 略高于参考，差异不显著（p = 0.28）。
- **需要实际求解的 228 个实例**：gpt-6.1-sol 在两种时限下都显著优于 Clarabel；重标定时限下为 132 对 93，p = 0.0035。优势集中在 PSD、SOC 和 LP。
- **1 秒下限**：650 例中 422 例的时限是 1 秒下限。候选提交每次运行多出 0.2–0.3 秒的启动开销，在这些小实例上大量刚好超时，这是它们整体成功率偏低的主要原因。
