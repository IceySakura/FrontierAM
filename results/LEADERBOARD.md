# FrontierAM 排行榜（本 x86_64 服务器，协议 v6，2026-11-04/05）

每个模型、每道题只有一次开发尝试：独占一个开发 slot（一个物理核），2 小时，工具环境断网，结束即冻结。只有冻结后的源码进入评测，并与在本机重跑的参考实现比较。证据在 `store*/`，方法细节见 `CONIC_FULL.md` 和 `CONCURRENCY.md`。

## 协议 v6

- 模型流量走 agent-traffic-runtime（ATR）。每个模型使用自己的原生 harness，推理强度、输出长度和上下文都设为 ATR 目录中验证过的最高值。
- harness 运行在断网的开发容器内，通过 Unix socket 连到宿主上的 `atr serve`。凭据只留在宿主，不进入容器。
- 开发容器以 UID 2000 运行。原因是 RLIMIT_NPROC 按 UID 在整台主机统计，评测器的进程上限会和开发 harness 的线程互相干扰（`CONCURRENCY.md` §5）。
- 客户端超时覆盖整个开发窗口：ATR 的非流式传输在长回答生成完之前不发送任何数据，原来的短超时会误判为失败。

**协议 v6.1**（11-05 起用于新的尝试，`--protocol v6.1`）：在 v6 的开发说明后追加一段，告诉 agent 开发核与其他尝试共享 L3 和内存带宽，开发时测到的耗时可能比评测慢 10–30% 且有波动，只适合做交替 A/B 的相对比较，以评测结果为准；并说明计时覆盖从进程启动到退出的全过程（含解释器启动和导入），每个时限都要留余量（`arena/native.py` 中的 `TIMING_NOTE`）。本榜单中的结果都是 v6。

## 锥优化（650 例全集，主榜）

参考为 Clarabel 0.11.1，已在本机全集上重跑。数字是三次重复都在时限内通过独立检查的实例数。"原时限"是题目包冻结的、按原机器标定的时限；"重标定"是用同一规则、按本机参考运行重新标定的时限。

| 模型（v6） | 原时限 | 本机重标定 | 时限 > 1 秒的 228 例（原时限 / 重标定） |
| --- | --- | --- | --- |
| 参考（Clarabel 0.11.1） | 447（0.688） | 513（0.789） | 36 / 93 |
| gpt-6.1-sol | **464（0.714）** | 467（0.718） | **130 / 132** |
| gpt-6-astra | 397（0.611） | 404（0.622） | 74 / 81 |
| hy4 | 336（0.517） | 339（0.522） | 60 / 61 |
| claude-opus-5-5 | 329（0.506） | 334（0.514） | 36 / 40 |
| deepseek-v4-pro | 全集未完成；20 例：0.20 | — | — |
| minimax-m3.1-flash | 全集未完成；20 例：0.10 | — | — |
| step-5-preview | 0（2 小时内无有效提交） | — | — |

要点（详见 `CONIC_FULL.md`）：

- **整体成功率**：在重标定时限下（题目的设计口径），没有模型超过参考。gpt-6.1-sol 最接近，但显著落后（p = 0.0048）。原时限下 sol 略高于参考，差异不显著（p = 0.28）。
- **需要实际求解的 228 个实例**：gpt-6.1-sol 在两种时限下都显著优于 Clarabel；重标定时限下为 132 对 93，p = 0.0035。优势集中在 PSD、SOC 和 LP。
- **1 秒下限**：650 例中 422 例的时限是 1 秒下限。候选提交每次运行多出 0.2–0.3 秒的启动开销，在这些小实例上大量刚好超时，这是它们整体成功率偏低的主要原因。
- **完整度**：deepseek 和 minimax 的全集评测没能在交付时间前完成，这里只列 20 例 pilot 结果（同期参考在这 20 例上为 0.50），仅供参考。

## 指数传播（参考偏弱，正在重做）

当前得分为 100 / (1 + R)，R 是相对参考的时间比，参考本身得 50。所有提交的配对 load factor 都低于 1.04 的闸门，用例全部有效。

| 模型（v6） | 得分 | load factor |
| --- | --- | --- |
| claude-opus-5-5 | 94.59 | 1.035 |
| gpt-6-astra | 90.43 | 1.033 |
| gpt-6.1-sol | 86.78 | 1.010 |
| hy4 | 81.21 | 1.012 |
| minimax-m3.1-flash | 70.92 | 1.014 |
| deepseek-v4-pro | 26.96 | 1.013 |
| step-5-preview | 0（第 1 次因 harness 超时设置作废；重跑后 2 小时内无有效提交） | — |

这组分数**不能**解读为超过人类 SOTA。参考是 KIOPS 跑在 Octave 解释器里；私有用例只有 n = 1.5k–3.2k，耗时以解释器开销为主；评分公式在高分段饱和。已经接入更强的 Expokit 参考（Sidje 1998 作者原码，编译执行），在公开用例上比 KIOPS 快约 25 倍，但还未建立 baseline。完整的重做方案（SuiteSparse 加合成算子的大规模数据集、多个人类已发表实现组成参照组、基于置信区间的判据）见 `tasks/exponential/sota_v1/DESIGN.md`。
