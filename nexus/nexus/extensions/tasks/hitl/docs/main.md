# HITL V2

HITL (Human in the Loop) 是一个为 nexus 扩展多轮 agent 交互与用户模拟的模块。HITL v2 基于 v1 开发，旨在提高 user sim 的多样性和通用性，为各 topic 提供开箱可用、便于二次开发的 user simulator 实现。

本文介绍 HITL 的动机、开发过程、预期收益与当前的欠缺。功能、状态与接入入口见 [overview.md](overview.md)。

## 设计动机

### 从单轮到多轮

现有大量的任务依旧建立在单轮的 agent 任务之上，由 Claude 在 harness 中自主从一个初始需求开始完成整个任务。然而，随着模型能力的提升、上下文长度的扩展和任务难度与规模的扩大，这样的数据生产管线逐渐不足以满足我们对于数据多样性和质量的要求。

### 从改造 nexus 开始

Nexus 原生为少部分 harness 提供了多轮调用的 API，它基于回调函数实现，提供了较好的可扩展性。但是，该实现方式在 user simulator 开发场景和大规模生产场景存在诸多缺陷和不方便之处：

- **user input 回调函数依赖 task 传入。** 意味着已有的 task 不能直接接入一个设计好的多轮 agent 实现，必须进行专门改造，引入了大量链路的不确定性。这也是多轮一直没能被广泛推广的原因之一。
- **并行支持不佳。** 基于回调的 agent fn 必须一次性在一个 session 上运行到 agent 结束，无法支持多 session 并行等语义。
- **轨迹追踪困难。** 为了在多 agent 场景下正确区分 chat tracker 记录的轨迹来源，会需要对沙箱内 agent 的 handler 和 runtime 做直接的操作，现有实现的封装导致无法实现这一点。
- **语义依赖。** 回调函数将 Claude Code session 本身作为循环主体，削弱了 user sim 以及多 agent 下总体编排的语义。

为了弥补上述缺陷，我们开发了 HITL，核心目标是为 nexus 扩展一套语义清晰、扩展灵活、开发方便的组件，并基于此探索、设计和验证 user simulator 在大规模数据合成上的效果和性能。

### HITL V1：对多轮合成管线的尝试

HITL v1 是我们在该任务上的最初尝试，它基于 SWE 任务进行了广泛的探索。我们最终形成的方案包括对数据本身的多轮化与一个轻量的 user simulator 设计，并在实验中验证了合成多轮数据对于模型 agent 能力的作用，尤其是 long horizon agent 任务与多轮任务的能力。

### HITL V2：迈向真正的用户模拟与多样化任务

HITL v1 提供了 SWE 任务的多轮化改造，然而它的 user sim 本身相当轻，大量行动以补充需求为主，和真实用户多样化的行为依旧有差距。同时，由于 v1 在探索时期的技术不成熟，诸多代码实现都耦合了多轮 SWE 任务本身，难以迁移到其他 topic 的任务上，在普通的单轮任务上表现也不佳。

为了弥补以上缺点，我们基于 v1 的脚手架重构并开发了 HITL v2，旨在设计更多样化的 user simulator，提供多轮交互与用户模拟的通用化基础设施，并尽可能在已有任务上直接验证其效果。

## 目标与收益

我们希望 HITL 能够全面的强化现有数据合成管线，具体包含以下方面

**多轮交互与 long running 轨迹** 通过 user 的追加、验证与打回等行为，这些轨迹在多样性与任务的完成度上都能得到显著的提升。同时，也能更高效的为 1M 上下文模型提供训练素材，支持后续 Hy 模型的长文能力提升。

**低适配代价与可扩展性** HITL 目标在不改变现在各 topic 已有的 one shot 任务和数据管线的前提下，仅通过少量适配工作即可产出多轮交互的 long running 轨迹。同时，支持各topic 根据自己任务的特点与领域内用户行为特征定制化调整 user simulator的配置。

**专项优化用户体验** 在 Hy 模型的基础能力达到可用水平后，我们需要开始思考如何优化模型的真实使用体验。HITL 从用户模拟与多轮化任务出发，计划在后续能够在用户建模、体验自动化评估、训练方案等方向全面的探索和验证，让 Hy 模型真正从可用变的好用。

## 未来计划

构建一个真正稳定、多样、可用的 user simulator 依旧是一个要长期探索和解决的难题，在 HITL 的后续开发中，我们也思考了一些主要的发展了以下方向：

- **接入 RL。** 多轮交互与用户模拟有机会提高现有任务的难度与多样性，从而提高 RL 模型的上限。但 user simulation 带来的rollout 代价、奖励归属等依旧需要进一步评估。
- **评估** HITL 希望在轨迹层能够直接衡量用户的交互体验，从而让任务生产脱离结果质量的单一指标；同时，当前仍然极度缺少与 user simulation 相关以及用户体验的 benchmark，因此 HITL 也会进一步探索如何直接构建相关的自动化评测。
- **真实行为模式的来源。** 从用户日志分析真实用户如何提出需求、何时不满、打回时如何表述等行为，并据此设计 persona。
