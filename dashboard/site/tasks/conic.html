凸锥优化求解器

数值优化 · 从零实现一个通用凸锥优化求解器，覆盖线性、二次、二阶锥、半正定和指数锥，650 个隐藏实例，逐例时限 1–300 秒（出题方 2026-11-05 修正版题包）。

题目背景

凸锥优化是运筹、控制、机器学习和金融里最常用的数学规划形式：在线性约束和锥约束下最小化一个凸二次目标。成熟的工业求解器（如 Clarabel、MOSEK、ECOS、SCS）都基于内点法或一阶方法，需要处理数值病态、不可行性判定（给出原始或对偶不可行证书）和从几十到上百万变量的规模差异。

这道题要求模型在 2 小时内、断网、只用 NumPy/SciPy 等已安装的库，从零写出一个通用求解器。难点不是某一类问题，而是在五类锥、各种规模和病态程度上都能在时限内给出通过独立检查的结果。

公开题面原文（给模型的版本）

题目名称

固定资源下的高精度凸锥优化求解

问题描述

实现一个通用求解程序，处理以下凸优化问题：

\[ \min_{x,s}\ \tfrac12x^\top Px+q^\top x+c_0, \qquad Ax+s=b,\quad s\in\mathcal K. \]

输入 含义
\(P\) \(n\times n\) 对称半正定稀疏矩阵
\(q\) 长度 \(n\) 的向量
\(A,b\) \(m\times n\) 稀疏矩阵与长度 \(m\) 的向量
\(\mathcal K\) 按约束行排列的锥块乘积，由 cones 列表描述；支持零锥、非负锥、二阶锥、指数锥和半正定锥
\(c_0\) 目标函数常数项，对应 objective_offset，无常数项时取 0

\(\mathcal K\) 是各锥块的笛卡尔积。零锥为 \(\{0\}^d\)，非负锥为 \(\mathbb R_+^d\)，二阶锥为 \(\{(t,v):t\ge\|v\|_2\}\)，半正定锥为实对称半正定矩阵的集合。指数锥定义为 \(K_{\exp}=\{(u,v,w):v>0,\ v e^{u/v}\le w\}\cup\{(u,0,w):u\le0,w\ge0\}\)。各锥块的向量编码见“交付要求”。\(\mathcal K^*\) 表示对偶锥，即与 \(\mathcal K\) 中任意向量的内积均非负的向量集合。

程序返回下列一种状态及对应向量：

status 含义 必需向量
solved 找到满足精度要求的最优解 x,s,z
primal_infeasible 判断不存在满足全部约束的解 z，用于验证这一判断
dual_infeasible 找到满足规定条件的下降方向；不单独表示原问题无界 方向向量 x,s
unresolved 未得到可验证的结果 无

x 长度为 \(n\)，s,z 长度为 \(m\)，均为一维有限实数数组。solved 中 x 是所求解，s=b-Ax，z 用于验证最优性；目标值由评测方根据 x 计算。其余状态的验证条件见“评测指标”。

算法目标

在规定精度和逐例资源预算内，提高正确求解的实例比例。算法路线和实现语言不限。

请自行检索相关论文与开源实现，调研当前先进方法，评估其在本题精度要求和资源限制下的适用性，并据此选择、实现或改进算法。可以采用、组合或改进已有方法，也可以设计新方法。调研说明不单独计分。

./run.sh --input INPUT_PATH --output OUTPUT_PATH

输入文件格式

NPZ 包含一维 float64 数组 q,b，以及 P_data,P_indices,P_indptr,P_shape、A_data,A_indices,A_indptr,A_shape 两组标准 CSC 数组。索引从 0 开始，重复位置求和，\(P\) 存储完整对称矩阵。所有系数有限，索引和维度合法，不使用对象数组或 pickle。输入对称性容许 \(\max_{ij}|P_{ij}-P_{ji}|/\max(1,\max_{ij}|P_{ij}|)\le10^{-12}\)。

metadata_json 为标量 Unicode 数组，内容为 JSON 对象，以下键均必需：

{"schema_version":1,"name":"instance_id","cones":[{"type":"nonnegative","dim":2}],"objective_offset":0.0,"metadata":{}}

cones 按约束行排列，恰好覆盖 \(m\) 行；dim 为正整数：

type dim 与编码
zero、nonnegative 向量长度
soc 向量长度，至少为 2；首项为标量，其余为向量部分
exponential 固定为 3，坐标顺序为 \((u,v,w)\)
psd 矩阵阶数 \(d\)，占 \(d(d+1)/2\) 行；上三角逐列排列，非对角项乘 \(\sqrt2\)

输出文件格式

NPZ 的 metadata_json 同样为标量 Unicode 数组，例如 {"schema_version":1,"status":"solved"}；schema_version 必须是整数 1。按状态提供 x,s,z；必需向量长度为零时仍须保存空数组，额外提供的向量也须满足对应维度。

solved 可在 JSON 中提供包含 \(c_0\) 的有限目标值 objective_primal、objective_dual，省略或 null 表示未报告。primal_infeasible、dual_infeasible 的目标字段须省略或为 null。JSON 不得含 NaN 或 Infinity。

评测指标

成功条件与计分指标

在固定的 650 个留出实例上评测，每例等权、运行三次；163 个公开实例供开发，不计入最终指标。各类别另报指标，不先按类别打分再平均。

唯一计分指标为成功率 \(p=k/N\)：\(k\) 是三次均在该例时限内通过独立检查且状态一致的实例数，\(N=650\)。成功率越高越好。运行时间用于判定是否超时，并保留实际耗时记录；更快、更低内存或更小数值误差不另加分。

每次以新进程顺序运行。计时从启动提交程序前开始，到检测到退出为止，包含加载、数据读写、实例相关准备、进程内编译、求解和恢复原坐标；不含通用构建、容器启停及独立检查。不逐例预热或清空系统缓存。

unresolved、超时、超内存、异常退出、输出缺失或格式错误、未通过检查或三次返回状态不一致，均使该实例计失败。失败不另设时间罚分。缺少必需提交文件、构建失败或运行入口无效时，整次提交计 0 分。评测程序或检查器故障不计为算法失败；评测记录缺失或无效时不产生有效总分。

0–10 分映射

令 \(p_B\) 为参考记录按本题时限和验收条件核算的成功率，满足 \(0<p_B<1\)。该参数由评测方预先固定，对所有提交一致使用，不公开具体值。

\[ S(p)=\begin{cases} 0,&0\le p\le0.9p_B,\\[3pt] 5\dfrac{p-0.9p_B}{0.1p_B},&0.9p_B<p\le p_B,\\[6pt] 5+5\dfrac{p-p_B}{1-p_B},&p_B<p\le1. \end{cases} \]

参考成功率对应 5 分，其 90% 及以下对应 0 分，100% 成功率对应 10 分。这里的 90% 是相对比例，不是减去 10 个百分点。评分参数不根据提交成绩调整。

计算使用完整精度，展示总分保留两位小数；若平台以 0–1 的 reward 返回成绩，其值为 \(S/10\)。先汇总每例的三次结果，再计算一次 \(p,S\)，不分别计算三轮总分后平均。

正确性条件

评测器使用原始输入及 float64 独立验解。未标下标的范数均为无穷范数，空向量范数为 0，\(\varepsilon=10^{-8}\)；所有检查计算须有限。

solved 须满足

\[ \begin{gathered} r_p=\frac{\|Ax+s-b\|}{1+\max(\|Ax\|,\|s\|,\|b\|)}\le\varepsilon,\qquad r_d=\frac{\|Px+q+A^\top z\|}{1+\max(\|Px\|,\|q\|,\|A^\top z\|)}\le\varepsilon,\\ C_{\mathcal K}(s)\le\varepsilon,\qquad C_{\mathcal K^*}(z)\le\varepsilon,\\ p_0=\tfrac12x^\top Px+q^\top x,\quad d_0=-\tfrac12x^\top Px-b^\top z,\quad |p_0-d_0|\le\varepsilon\ \ \text{或}\ \ \frac{|p_0-d_0|}{\max(|p_0|,|d_0|)}\le\varepsilon. \end{gathered} \]

两目标均为 0 时相对间隙取 0。若报告目标值，另要求 \(|p_{\rm reported}-(p_0+c_0)|/(1+|p_0|)\le\varepsilon\)，对偶目标同理。\(|s^\top z|\) 仅作诊断，无独立通过阈值，但须有限。

锥缺陷。 对每块令 \(u=v_{\rm block}/\max(1,\|v_{\rm block}\|)\)，\(C_{\mathcal K}(v)\) 取所有块缺陷的最大值（空列表取 0）。记 \(r_+=\max(r,0)\)，各块缺陷为：

锥 块缺陷
零锥 \(\lVert u\rVert_\infty\)
非负锥 \((-\min_j u_j)_+\)
二阶锥 \((\lVert u_{2:}\rVert_2-u_1)_+\)
半正定锥 \((-\lambda_{\min}(\operatorname{smat}(u)))_+\)，smat 为“交付要求”所定义 PSD 编码的逆变换
指数锥 \(E(u_1,u_2,u_3)\)

\[ B(a,b,c)=\max(|b|,a_+,(-c)_+),\qquad E(a,b,c)=\begin{cases} \min\{B(a,b,c),[a-b(\log c-\log b)]_+\},&b>0,c>0,\\ B(a,b,c),&\text{其他情况}. \end{cases} \]

对偶锥使用相同规则，但零锥的对偶缺陷为 0，指数锥的对偶缺陷为 \(E(-u_2,-u_1,e u_3)\)；变换后不再归一化。PSD 直接计算最小特征值。

不可行证据。 令 \(a=\max_{ij}|A_{ij}|\)、\(h=\max_{ij}|P_{ij}|\)，全零或空矩阵的尺度取 1。

  • primal_infeasible：要求 \(\|z\|,\|b\|>0\)。令 \(\hat z=z/\|z\|\)、\(\beta=-(b/\|b\|)^\top\hat z\)，须满足

\[ \beta>\varepsilon,\qquad \frac{\|(A/a)^\top\hat z\|}{\beta}\le\varepsilon,\qquad \frac{C_{\mathcal K^*}(\hat z)}{\beta}\le\varepsilon. \]

  • dual_infeasible：要求 \(\|x\|,\|q\|>0\)。令 \(\hat x=x/\|x\|\)、\(\hat s=s/\|x\|\)、\(\alpha=-(q/\|q\|)^\top\hat x\)，须满足

\[ \alpha>\varepsilon,\qquad \frac{\|(P/h)\hat x\|}{\alpha}\le\varepsilon,\qquad \frac{\|(A/a)\hat x+\hat s/a\|}{\alpha}\le\varepsilon,\qquad \frac{C_{\mathcal K}(\hat s/a)}{\alpha}\le\varepsilon. \]

对偶不可行证据不自动表示原始问题无界。

模型自己写的说明（提交中的 README.md）

Offline Conic Solver

Build and run:

./build.sh
./run.sh --input /absolute/problem.npz --output /absolute/result.npz

The implementation uses the preinstalled Python 3.12.14, NumPy 2.3.5, SciPy 1.16.3, and the HiGHS 1.8.0 extension distributed inside SciPy. The small native helper is compiled with the installed GCC 12.2 C++ compiler. There are no network operations or downloaded dependencies.

build.sh compiles the native helper and prepares Python import caches. All generated build artifacts remain in this directory. Solving is single-process and numerical libraries are restricted to one thread. The inherited CPU affinity is left unchanged.

Methods

  • Linear optimization uses HiGHS, with explicit alternative problems for infeasibility certificates.
  • Suitable polyhedral QPs use an objective-scaled HiGHS active-set solve. Other quadratic and symmetric-cone problems use a homogeneous primal-dual predictor/corrector method, equilibration, reusable native sparse LDL factors, and iterative refinement. A small-QP operator-splitting fallback includes active-set polishing.
  • Lorentz scalings use extended-precision geometry and sparse low-rank augmented systems to avoid cancellation close to the boundary.
  • Semidefinite blocks use isometric upper-triangle coordinates, Nesterov--Todd scalings, and dense Schur complements formed by native code.
  • Exponential cones have a normalized homogeneous barrier-Newton fallback. Recognized exponential epigraphs are reduced algebraically to convex log-sum-exp constraints, solved by a dense reduced primal-dual method, and reconstructed in the original conic coordinates.
  • Sparse equality substitutions and constant-row removal are reversible. Very large models also have an exact null-cost feasibility presolve. Recognized weighted least-squares/L1 epigraphs use native coordinate descent with full primal and dual recovery. Termination checks use residuals, cone membership, and primal/dual gaps; infeasibility outputs use homogeneous certificates.

The public development examples and the supplied independent checker are used for testing. This is a locally implemented solver, not a claim of complete coverage of every ill-conditioned conic problem.

  • Y. Nesterov and M. J. Todd, "Self-Scaled Barriers and Interior-Point Methods for Convex Programming," Mathematics of Operations Research, 1997.
  • A. Skajaa and Y. Ye, "A Homogeneous Interior-Point Algorithm for Nonsymmetric Convex Conic Optimization," Mathematical Programming, 2015.
  • P. Goulart and Y. Chen, "Clarabel: An Interior-Point Solver for Conic Programs with Quadratic Objectives," 2024.
  • T. A. Davis, "Algorithm 849: A Concise Sparse Cholesky Factorization Package," ACM Transactions on Mathematical Software, 2005.
  • B. Stellato et al., "OSQP: An Operator Splitting Solver for Quadratic Programs," Mathematical Programming Computation, 2020.

Portable Conic Solver

Build and Run

./build.sh
./run.sh --input /absolute/input.npz --output /absolute/result.npz

The build compiles the C++ numerical/presolve helper and prepares reusable Python bytecode. It does not inspect any problem input. The run script uses exec; all problem-dependent work is performed in the solver process. Input and output use the schema-1 NPZ interface, without pickle.

Dependencies are the preinstalled Python 3.12.14, NumPy 2.3.5, SciPy 1.16.3, and g++ 12.2.0. SciPy supplies HiGHS 1.8.0, SuperLU, BLAS and LAPACK. The target is Linux amd64. No network access or package installation is required. Numerical libraries are restricted to one thread and CPU affinity is inherited. Startup avoids importing NumPy's unused testing and Fortran-compilation front ends into SciPy's compatibility namespace; NumPy's exports are restored immediately after that import.

Methods

  • Sparse affine union-find and singleton-equality substitution remove redundant lifted variables. Primal vectors and adjoint multipliers are restored to the original coordinate system. Constants introduced by substitution are retained in the relative-gap scale, separately from the input objective offset.
  • Polyhedral problems use HiGHS simplex, IPM and convex QP routines, with original-system KKT refinement. Bounded alternative LPs recover Farkas separators or recession directions when needed.
  • A homogeneous primal-dual predictor-corrector method handles general product cones. It uses Nesterov-Todd scaling for SOC and PSD blocks, sparse Schur systems, iterative refinement, and dense PSD operators without materializing a full Kronecker matrix.
  • Separable exponential epigraphs are reduced to log-sum-exp and exponential constraints, solved by a damped primal-dual Newton method with active-set refinement. A logarithmic-barrier conic method handles other exponential structures.
  • Low-rank polyhedral QPs can use fully corrective conditional gradients with warm LP oracles. Semidefinite certificate refinement uses affine and cone projections. Experimental reduced-space and LDL variants remain available in the source but are not the default linear-system path.

Every returned optimum or certificate is checked against the original input: finite dimensions, scaled primal/dual equations, cone defects, objective gap, and the contract's normalized certificate tests. An unverified candidate is reported as unresolved. Objective constants are not reported; the evaluator computes objectives from the original input. The PSD representation is the specified upper-triangle column ordering with square-root-of-two off-diagonal scaling.

Development Evidence

Formal public subset evaluations were used to select numerical paths. One 131-case checkpoint verified 97 cases, including 8/9 exponential and 6/9 PSD cases. These are single-run development results, not a claim about held-out results or three-repeat success. Short-limit timing tests favored the native LP path, sparse equality preprocessing and exponential epigraph elimination. Numerical experiments that regressed verified cone cases were not selected as defaults.

Native conic interior-point solver

How to run

./build.sh                                  # compiles src/solver.cpp -> bin/solver
./run.sh --input IN.npz --output OUT.npz    # execs bin/solver
  • build.sh takes no arguments and exits 0. If the compile ever fails, it copies bin/solver.prebuilt to bin/solver. That binary was built from the same sources in this image.
  • run.sh sets OPENBLAS_NUM_THREADS=1 and execs the binary.
  • The solver always writes the output NPZ and exits 0, including when the result is unresolved.
  • Diagnostics go to stderr only when SOLVER_VERBOSE=1 (or 2, 3) is set.
  • No temporary files are written.

Dependencies and pinned versions (all preinstalled; nothing is downloaded)

  • g++ 12.2.0 (C++17): one translation unit, src/solver.cpp, plus two headers:
  • src/npzio.hpp: zip/NPY reader and writer.
  • src/amd.hpp: approximate minimum degree ordering.
  • zlib 1.2.13 runtime (libz.so.1): inflates the deflate-compressed NPZ inputs. There is no zlib.h in the image, so the prototypes and the z_stream layout are declared in npzio.hpp.
  • Reference LAPACK/BLAS 3.11 (liblapack.so.3, libblas.so.3): used for the small dense operations of PSD cones (Cholesky, SVD, symmetric eigenvalues, gemm). When PSD cones are present, the solver dlopens the OpenBLAS that ships inside the preinstalled SciPy 1.16.3 wheel (scipy.libs/libscipy_openblas-*.so, symbols scipy_d*_) and runs it single-threaded. If that library is missing, it silently stays on reference LAPACK.

There is no Python at solve time. Process start-up takes milliseconds. That matters because most instances have a 1 s limit, and import numpy, scipy.sparse alone takes about 0.7 s on this machine.

Method

Problem: min ½x'Px + q'x s.t. Ax + s = b, s ∈ K, with K a product of zero, nonnegative, second-order, exponential and PSD cones.

The solver is a homogeneous self-dual embedding interior-point method with a quadratic objective, following Clarabel (Goulart & Chen 2024).

  • Presolve and scaling:
  • Duplicate entries are summed and explicit zeros dropped.
  • Consecutive zero and nonnegative cones are merged.
  • Ruiz equilibration (up to 10 passes, stopping early once the factors have converged; factors bounded to [1e-4, 1e4]) is applied to the KKT matrix, with uniform row scaling inside each SOC/exp/PSD block, followed by cost scaling.
  • Initial point:
  • Symmetric cones: the Clarabel/CVXOPT least-squares point (solved with H = I), shifted into the cone interior.
  • When exponential cones are present: the unit point (central ray of the exp cone).
  • Iteration: a Mehrotra predictor-corrector on (x, s, z, τ, κ). Each iteration does one factorization and three solves (the constant [-q; b] system, the affine step and the combined step). Δτ is eliminated with the numerically stable denominator -(z1'Hz1 + ‖x1-ξ‖²_P + κ/τ). Step fraction is 0.99, and σ = (1-α_aff)³.
  • Scalings:
  • Nonnegative and second-order cones: Nesterov–Todd scaling. The SOC uses a stable residual (x0-‖x1‖)(x0+‖x1‖), Clarabel-style renormalisation of w, and W'λ as the affine-step right-hand side.
  • PSD cones: NT scaling from R = L_s V Λ^{-1/2}, where L_z'L_s = UΛV'.
  • Exponential cones: dual-barrier scaling μ∇²f*(z) with centering s + σμ∇f*(z). The step length uses backtracking with barrier-domain checks. On the development set this was much faster than the Dahl–Andersen primal-dual scaling variant, which is still available with EXP_PD=1.
  • Linear algebra:
  • The quasi-definite KKT matrix [[P+δI, A'], [A, -(H+δI)]] is ordered with AMD (a port of CSparse cs_amd) and factored with an up-looking sparse LDLᵀ (the QDLDL algorithm).
  • Static regularization δ = 1e-8, plus sign-aware dynamic pivot regularization.
  • Iterative refinement runs against the unregularized matrix. Its relative tolerance is min(1e-9, max(1e-13, 1e-6·μ)) for problems without SOC cones, and 1e-13 otherwise.
  • Second-order cones are eliminated analytically: A_c'H_c⁻¹A_c is added to the x-block, using the exact inverse H⁻¹ = η⁻²(2ŵŵ' − J), ŵ = Jw. Near the boundary, the dense -(H+δI) SOC blocks (condition number ~1e18) produced wrong-sign pivots. The reduced solve is then refined against the full unreduced system (up to 10 steps). An SOC whose rows touch more than 200 columns keeps its dense -(H+δI) block in the KKT instead, which prevents a dense |J_c|² fill.
  • PSD-dominated problems (only PSD and nonnegative cones, n ≤ 6000) use a dense Schur complement (normal equations) P + Σ A_c'H_c⁻¹A_c instead of the sparse KKT. Forming it exploits the sparsity of each column of A via G_j = B⁻¹ S_j B⁻¹ with B = RR'. It is then factored with dense Cholesky and the solves are refined.
  • Safeguards:
  • If a step makes a nearly converged iterate ≥10× worse (or non-finite), the step is undone and redone with a different static regularization and a damped step.
  • The best iterate that satisfies the tolerance is kept.
  • Retries with larger regularization run if a factorization fails.
  • Termination:
  • The independent checker's formulas are evaluated each iteration in the original coordinates (primal and dual residuals with their normalisations, absolute or relative gap) against 0.9·1e-8.
  • Before a result is reported as solved, it is re-verified with the original matrices.
  • Primal and dual infeasibility certificates are tested each iteration with the checker's normalised conditions (A/max|A|, P/max|P|, b/‖b‖, q/‖q‖).
  • Output: vectors are mapped back to the original coordinates. s is exactly 0 on zero-cone rows. The objective fields are omitted (they are optional).

Conic solver (HSDE interior point, native C++)

Running

./build.sh                                   # compiles ./solver (g++ -O2, ~5 s)
./run.sh --input IN.npz --output OUT.npz     # exec's ./solver

run.sh uses exec to start the native binary. No Python at solve time: importing numpy+scipy alone costs ~0.7 s, which would make the 1-second instances impossible.

Dependencies (all preinstalled in the image, nothing downloaded)

  • g++ 12.2.0 (C++17)
  • system zlib libz.so.1 (1.2.13), used only to inflate the NPZ input; declared manually because no zlib headers are installed
  • reference LAPACK/BLAS (liblapack.so.3 3.11.0, libblas.so.3), used only for PSD cones (dpotrf, dgesvd, dsyev)

Method

  • Formulation: homogeneous self-dual embedding for QP objectives, following Clarabel (Goulart & Chen, "Clarabel: an interior-point solver for conic programs with quadratic objectives", 2024). Predictor-corrector with σ = (1-α_aff)^3 and a Mehrotra second-order correction for symmetric cones. Uses a 0.99 fraction to the boundary.
  • Scaling: Nesterov–Todd for nonnegative, SOC (Lorentz hyperbolic-rotation form as in ECOS/Clarabel) and PSD (chol+SVD form as in CVXOPT). Exponential cone uses dual scaling μ∇²F*(z) with the explicit dual barrier, plus a barrier-based neighbourhood line search (Skajaa–Ye / ECOS-exp style).
  • Linear algebra: own up-looking sparse LDLᵀ (QDLDL algorithm, Stellato et al.) with static (1e-8) and sign-aware dynamic regularization, an AMD fill-reducing ordering (re-implementation of CSparse cs_amd, T. Davis), and iterative refinement.
  • Improvement over the plain Clarabel KKT for SOC: near the optimum the NT block η²(2wwᵀ−J) loses its small eigenvalue in floating point (w₀ grows like μ^-½), giving wrong-sign pivots. For SOC blocks of dimension ≤ 16 the factorized matrix uses the W-scaled form [P, (W⁻¹A)ᵀ; W⁻¹A, −I]. That matrix is used only as a preconditioner: iterative refinement runs against the original KKT system, with H applied as W(W·), because K = diag(I,W)·K'·diag(I,W). Δs on SOC rows is taken from the linearized primal equation, which keeps primal residuals consistent. Experimental basis: on the public SOC instances this changed every case from stalling at about 1e-8 to verified.
  • PSD problems (nonnegative + PSD cones only, n ≤ 6000): these problems use a reduced normal-equations solve instead of the dense svec KKT blocks. The solve forms M = P + δI + AᵀH⁻¹A, with H⁻¹(X) = QXQ and Q = R⁻¹ from the NT scaling. M is assembled entry by entry from pairs of A's PSD nonzeros (H⁻¹[(ij),(kl)] = s_ij s_kl (Q_ik Q_jl + Q_il Q_jk)/2), then factored with dense Cholesky, as in classical SDP codes (SDPA/CSDP). This is used as the preconditioner of the same iterative refinement. Experimental basis: public PSD orders 100, 150 and 200 solve in 1.1 s, 5 s and 19 s. Previously they were impossible: a dense 11k–20k block in the sparse LDLᵀ.
  • Exponential cone line search: if the centrality backtracking cannot find an acceptable step (the current point already lies outside the neighbourhood), the solver takes 0.9× the feasible step instead of stalling. On the public set this took the exponential group from 5/9 to 7/9 solved.
  • Iterative refinement and retries: refinement stops at 1e-12 absolute plus 1e-12 relative, which is about 15–25% faster on the 1-second LP/QP instances than 1e-13/1e-14. If a solve ends unresolved, the problem is solved again from scratch with tight refinement (1e-13/1e-14). SOC problems also get a third attempt with plain H-form SOC blocks. These attempts are deterministic, and a result is returned only after it passes the exact acceptance checks.
  • Equilibration: Ruiz scaling of [P Aᵀ; A 0], uniform within non-separable cone blocks, and cost scaling as in Clarabel.
  • Initialization: Clarabel-style KKT initialization with H = I when all cones are symmetric, and the central-point unit initialization when exponential cones are present.
  • Termination: each iteration evaluates the official acceptance tests (relative primal/dual residuals, duality gap, infeasibility certificates with the matrix scalings a and h) on the original unscaled data, with a 0.9·1e-8 safety margin. It returns as soon as one passes. Result vectors are mapped back to the original coordinates; zero-cone slacks are set exactly to 0.

Limitations

Outside the reduced path (for example PSD mixed with zero or SOC cones), PSD cones go into the KKT system as dense blocks, and cones with more than 1300 svec entries are reported unresolved immediately. Large SOC problems can still stall in the last iterations.
