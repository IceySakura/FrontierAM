稀疏系统的指数传播（对标人类 SOTA）

数值线性代数 · 对大型稀疏对称半正定矩阵计算 \(e^{-tL}b_0 + t\varphi_1(-tL)b_1\)，在给定精度下越快越好；参照是 7 个已发表方法逐例取最快者。

题目背景

求矩阵指数作用在向量上的结果 \(e^{-tL}b\)（以及带源项的 \(\varphi_1\) 函数）是求解刚性线性常微分方程、热传导和扩散过程、图上信息传播和指数积分器的核心操作。矩阵太大不能直接求矩阵指数，主流方法是 Krylov 子空间（Lanczos、自适应 Krylov）、缩放加截断 Taylor、在谱区间上做 Chebyshev 展开，以及有理/移位求逆 Krylov。好的实现要根据矩阵的谱范围、精度要求和右端数量选方法，并在多个右端之间复用计算。

这一版的设计原则是学术上可信：参照组只用已发表的方法和作者代码或公认的库，参数只在公开数据上标定并在任何模型提交之前冻结；私有测试集在参照组冻结之后才生成。因此“超过参照组”意味着在这些用例上快于已发表的最好方法。

公开题面原文（给模型的版本）

稀疏系统的指数传播

实现一个程序，在给定精度和资源预算下，尽快完成一个数值计算会话。会话固定实对称半正定稀疏矩阵L、时间t和误差要求，依次收到一个或16个向量对。对第j个向量对，返回完整向量

\[ y_j=e^{-tL}b_{0,j}+t\varphi_1(-tL)b_{1,j},\qquad \varphi_1(z)=\sum_{k=0}^{\infty}\frac{z^k}{(k+1)!}. \]

矩阵函数由同一幂级数定义，phi1(0)=1；L可以奇异。等价地，这是u'(s)=−Lu(s)+b1、u(0)=b0在s=t的状态。t=0时结果为b0。不要假设L可逆、每行和为0、非对角元非正或向量非负。

输入范围和会话

  • 1≤n≤120000，非零数nnz≤1000000；输入为完整CSR矩阵而非只存上三角。
  • L数学上实对称半正定；所有存储值均为有限binary64。实际收到的矩阵是计算对象，不要求重建生成器的理想矩阵。
  • 0≤t≤10000，||L||∞≤1e8，t||L||∞≤1e5；这里矩阵无穷范数为最大绝对行和。
  • 每个右端分量在[−1,1]。允许零矩阵、零向量和零特征值。
  • one_shot会话只有1个请求；reuse会话有16个请求。同一会话的L、t和精度固定，只有b0、b1改变。
  • 下一请求在上一请求完整输出后才揭露。你可以在会话内保存和复用任何合法状态；不能预先获取后续右端。每个会话和每次统计重复均从干净进程开始。

算法自由。可以使用预装数值库及其高层函数，也可以自行实现、组合或修改算法。资源限制内的时间空间取舍合法；所有与当前输入有关的准备工作、缓存及临时数据都纳入本次资源计量。

精度

会话指定以下一个精度档；程序不得自行改变：

档位 rtol atol
p4 1e−4 1e−7
p7 1e−7 1e−10
p10 1e−10 1e−13

对每个完整输出，裁判独立检查

max(abs(y-y_ref)) <= atol + rtol*max(abs(y_ref))。

这是全向量的混合绝对相对无穷范数，不是每个分量分别作相对误差。所有输出必须有限，所有请求和三次重复均须通过。独立参考未具备可靠精度时属于评测故障，不记为你的错误。

接口和计时

实现标准输入/输出进程接口，详细字节布局见API.md。准备好接收输入后，只输出READY加换行并刷新。此时尚未提供L、t或任何右端。初始化最多15秒。

控制器在交付矩阵第一个字节前开始计时；时间覆盖矩阵读取、转换、输入相关准备、全部请求和输出，终点取全部输出收齐与程序正常退出两者较晚的时刻。允许在READY之前导入通用库或完成与输入无关的初始化；不允许提前读取会话输入。普通离线构建另有预算，其费用不除以统计重复次数摊入主分；输入相关生成代码或即时编译仍计入会话时间。

输出只能包含READY行及各请求的原始向量字节。诊断写stderr。不得输出自报score、计时或正确性来替代裁判结果。

评分

同一会话独立运行三次，取完整数值会话时间的中位数，内存取三次最大值。任何必做会话、请求、格式、精度或资源检查失败，主分为0，同时给出开发覆盖率和失败反馈。不能只选成功子集。

完整合格时，令r_i=T_i/T_ref_i。先在同母算子的工作负载内平均，再依次按母算子、结构族、会话场景和精度档等权平均，得到R；主分为100/(1+R)。同一母算子的变体不会自动变成独立结构证据。控制例必须通过，但不参与时间均值。评分实现公开，见tools/scoring.py。

参考自身为50分；每项时间均减半为66.67分。内存仅设硬上限并单列报告，不为省内存额外加分。超过50意味着约定平均归一化时间下降，不表示每例都更快、每项内存都更低，或已经证明研究突破。

最终参考由维护者在相同环境中预先冻结，是可执行策略，不逐例事后选最快方法。参考代码和最终测试时延不向开发阶段开放。当前修订包尚无正式标定参考，本地工具返回原始指标，score为null；它不会拿旧计时冒充新协议成绩。

指数传播 v2 修订说明（优先于 INSTRUCTION.md 与 PILOT.md 中的对应条款）

接口（FAMEXP2）、精度判据、每会话资源上限、构建规则、tools/run_local.py 与 tools/scoring.py 均与原版相同。以下三点改变：

1. 参考时间：已发表人类方法的逐例最快值

原文“最终参考是一个可执行策略，不逐例事后选最快方法”作废。v2 的参考是一组事先冻结的人类参照实现（panel），全部来自已发表的方法和作者代码：对称 Lanczos/Krylov、自适应 Krylov 的 φ 函数组合、截断 Taylor 加缩放（两种实现）、谱区间上的 Chebyshev 展开。参数只在公开开发数据上按事先声明的规则选定，在任何 agent 提交之前冻结。

评测时，每个用例的参考时间 T_ref_i 取该用例上三次全部合格的 panel 成员中，中位时间最短的那一个。之后的层级平均与 tools/scoring.py 完全相同，主分仍为 100/(1+R)：参考自身为 50 分；平均归一化时间减半为 66.67 分。panel 源码与私有计时不提供给开发阶段。

2. 数据规模

正式测试的算子规模在 n 2 万至 12 万、nnz 不超过 100 万之间。来源包括标准稀疏矩阵集合中的有限元/扩散矩阵和真实网络图（转为组合拉普拉斯），以及合成的扩散、几何图、重尾网络、带符号关联矩阵和对数谱算子；t·||L||∞ 从 1e-2 到 1e5 分层。母算子在公开集与测试集之间不重合。

每个用例的计时是从第一个请求发出到最后一个结果返回（reuse 为 16 个请求依次往返），进程启动不计入时间，但单会话墙钟与 CPU 上限不变（one_shot 60 秒，reuse 240 秒）。

3. 公开开发数据

  • dev/：缩小规模的冒烟集，56 个用例（8 个母算子 × 3 精度 × 2 场景，加 8 个解析控制例），覆盖全部结构族与场景。
  • dev_full/（若存在）：正式规模的公开母算子上的 one_shot 用例。reuse 用例在正式规模下每个约 30 MB，开发空间放不下，因此不随包提供；可以用同一个 one_shot 用例连续发送多个请求来估计 reuse 的表现。

所有参考输出都经过两种独立方法交叉验证：扩展精度 Chebyshev 展开为主，双精度截断 Taylor 审计，两者差异不超过容差的 2%（审计方法不可靠的病态例改用稠密特征分解仲裁）。

运行示例：

模型自己写的说明（提交中的 README.md）

Sparse Exponential Propagation

This submission implements the FAMEXP2 binary streaming protocol in C++17. Build offline with bash build.sh, then run ./run.sh. The build requires the installed GNU C++ compiler and the standard C++ and C runtime libraries only. The executable uses the inherited CPU affinity and starts no worker threads.

The constant source is folded into the initial state as b0 + t*b1, since a constant source can be propagated from the beginning of the interval. The general solver therefore expands exp(-t*L)*(b0 + t*b1) in Chebyshev polynomials on a certified spectral interval for the received symmetric PSD matrix. Both terms are evaluated together using a Reinsch-modified Clenshaw recurrence, requiring one sparse matrix-vector product per polynomial degree. Scaled modified Bessel coefficients are generated by a backward ratio recurrence; integrated coefficients follow from positive coefficient sums. Euclidean coefficient-tail bounds determine the truncation degree. A posteriori output scaling can trigger a tighter evaluation. Stiff high-accuracy cases use extended-precision arithmetic. Coefficients and matrix preparation are retained only within the current session.

Zero times and zero matrices are handled directly. Matrices whose connected components have at most two vertices use cached analytic 1x1 and 2x2 matrix functions, including their singular eigenvalues.

Standard output contains only READY\n and the requested binary result vectors. Set FAMEXP_DEBUG=1 to send polynomial degrees to standard error.

The protocol and earlier numerical implementation were checked against all 56 reduced-size and 40 full-size public cases. The final shared-coefficient simplification was rebuilt and checked for standalone startup.

模型自己写的说明（提交中的 README.md）

Exponential Propagation

This submission implements the FAMEXP2 binary streaming protocol in C++17 for real symmetric positive semidefinite CSR matrices. It computes exp(-t L) b0 + t phi1(-t L) b1, including singular operators.

The executable uses only the C++ standard library. Building requires the installed GCC toolchain on Linux amd64. No downloads, network access, Python packages, agent tools, external data, or cross-session caches are required.

Build with bash build.sh, then run ./run.sh. The launcher automatically builds if the executable is absent. build.sh is the offline build entry point for the evaluator. All paths are relative to this directory.

Numerical Method

The general solver applies both functions in a single Chebyshev expansion. Scaled modified Bessel coefficients are generated by a backward ratio recurrence in extended precision. The phi1 coefficients follow from a backward integrated coefficient recurrence. A combined Reinsch/Clenshaw recurrence uses one sparse matrix-vector product per polynomial degree for the sum of the two functions.

The spectral upper bound uses absolute row sums followed, where useful, by positive-vector Collatz bounds for the absolute matrix. Euclidean-norm coefficient-tail bounds are checked against the requested infinity-norm tolerance, with a safety margin. For matrices with nonpositive off-diagonal entries, row-difference products reduce cancellation near the nullspace.

Small scaled norms use an adaptive Taylor series. Localized inputs may also finish before global preparation: for PSD matrices, the phi1 Taylor remainder is bounded by the Euclidean norm of its first omitted term. Disconnected scalar and 2x2 blocks have direct spectral formulas. PSD contractivity also permits zero output when its full norm bound is below half the absolute tolerance. Metzler generators use an additional infinity-norm semigroup bound for this check.

Original matrix entries and extended-precision coefficients are retained. Cancellation-heavy outputs are recomputed in extended precision, using the original entries rather than rounded normalized coefficients. This protects small absolute outputs as well as relative accuracy.

Generic buffers are allocated before READY; no input is read before it. All matrix-dependent work occurs after READY, and each complete result is flushed before reading the next request. The process exits after the last result. It uses the inherited CPU affinity and creates no worker threads.

Public Checks

Run the standalone standard-library protocol checks with:

python3 selftest.py

Development validation included:

  • All 56 reduced-size public smoke sessions, three repeats each.
  • All 40 full-size public one-shot sessions, three repeats each.
  • All 72 formal public evaluator sessions, including sequential reuse.
  • 60 additional sessions with 960 outputs checked against independent 75-digit eigendecomposition references, including constructed cancellations, singular signed operators, PSD Gram matrices, and stiff 2x2 blocks.
  • A maximum-size signed stress operator: 120,000 rows, 840,000 nonzeros, p10 accuracy, and scaled infinity norm 100,000. All 16 requests, including extended-precision recomputation, finished in approximately 102 seconds locally, below the 240-second limit, with reported peak RSS about 147 MiB.

FAMEXP2 exponential propagation: Chebyshev solver in C

./run.sh starts a compiled C program (expo.c + cheb_body.h). The program speaks the FAMEXP2 wire protocol directly on fds 0/1. It computes, for every request,

y = exp(-tL) b0 + t*phi1(-tL) b1        (L symmetric PSD, CSR input)

Files

file purpose
run.sh entry point; picks a prebuilt binary that passes --check on this CPU, else compiles expo.c with gcc
expo.c I/O, setup, spectral bound, ordering, SELL-4 build, AVX2 kernels, driver
cheb_body.h Chebyshev recurrence kernels and solver, instantiated for double and long double
expo_v3, expo_v1 prebuilt binaries (-O3 -march=x86-64-v3 with AVX2/FMA kernels, and baseline x86-64)
build_binaries.sh rebuilds both binaries from source (used during development; no build.sh is needed)

Dependencies: Linux, the C library and libm only. No Python, NumPy or BLAS is used at run time. gcc is needed only if neither prebuilt binary runs.

Algorithm

  1. Input-independent setup, before READY (untimed). A 64 MiB arena is mapped, advised for transparent huge pages and pre-faulted. Pipe buffers are enlarged to 1 MiB. The binary self-test (--check) runs from run.sh before the solver starts.
  2. Matrix read. The raw CSR arrays are read straight into the arena. The Gershgorin bound G = max_i sum_j |L_ij| is computed for complete rows while the value array is still arriving.
  3. Spectral interval [0, lh]. By default lh = G. When the expansion is long (estimated degree > 90 for one_shot, > 25 for reuse), a 12–80 step Lanczos run estimates lambda_max. It stops when the top Ritz value has converged, and then lh = theta + max(2% theta, 1.5 * residual), capped at G.
  4. Chebyshev expansion. On [0, lh], exp(-t lambda) has coefficients c_k = 2 (-1)^k e^{-beta} I_k(beta) with beta = t*lh/2. These are computed with Miller's backward ratio recurrence. The coefficients d_k of g(lambda) = (1 - e^{-t lambda})/lambda = t*phi1(-t*lambda) (no removable singularity at 0) come from a stable backward recurrence that inverts multiplication by (x+1). Tail sums sum_{j>k} |c_j|, sum_{j>k} |d_j| are tabulated.
  5. Forward three-term recurrence. v_{k+1} = 2 A~ v_k - v_{k-1} with A~ = (2/lh) L - I is run on b0 and b1 together: either one vector, when one right-hand side is zero, or an interleaved pair. Each step is fused with the accumulation y += c_k v0_k + d_k v1_k. The loop stops at the first k with 3 * (tail_c(k) * V0 + tail_d(k) * V1) <= atol + 0.98 * rtol * ||y_k||_inf, where V is the largest ||v_j||_inf seen so far. The criterion is therefore adaptive to the requested precision and to the actual size of y.
  6. Safety nets. * Interval check. With a correct interval, ||T_k(A~) b||_2 <= ||b||_2. If any step exceeds this by 1e-6 relative, the Lanczos interval was too small, and the request is recomputed on the rigorous Gershgorin interval. * Rounding check. For large t, rounding errors in near-null modes are amplified by up to max g = t. After each solve, the bound 1.1e-16 * (deg+10) * (||b0||_inf + t ||b1||_inf) * max(1, G/lh) is compared with 0.25 * (atol + rtol*||y||_inf). When the bound is larger, a twin solve runs first: the same polynomial at the same degree, with the right-hand sides scaled by pi/4. Scaling changes every rounding but leaves the mathematics and the truncation identical, so the difference between the two results measures the rounding error. If the two agree within 0.1 * tol, their average is returned. Otherwise the request is recomputed with the same recurrence in x87 extended precision (long double). On the public data the twin check accepted cases with differences 100–10000× below the tolerance. It sent exactly the requests that need extended precision (log-spectrum operator, t = 1e4) to the redo. A wall-time guard keeps all redos inside the session budget. * Trivial sessions (t = 0 or L = 0) return b0 + t*b1 exactly.
  7. Fast kernels. The sampled mean |i-j| of the nonzeros measures locality. SELL-4 is built when enough steps are expected: at least 8 for local orderings, at least 30 for random-access ones. If at least 150 steps are expected and the ordering is non-local, a BFS (Cuthill–McKee-like) order is tried. It is kept only if it halves the mean |i-j|, which happens for randomly numbered geometric graphs. Rows are sorted by length inside windows of 32. Chunks of 4 rows are stored column-major, so the gather and FMA chains of 4 rows run in parallel. On local orderings, AVX2 versions of the kernels are used (about 20% faster per step). On random-access graphs the scalar 4-row kernel is faster and is kept. Vectors are permuted on input and un-permuted on output. Cases with very few steps use the plain fused CSR kernel.

Reuse sessions share the setup (interval, coefficients, ordering, SELL arrays) across all 16 requests. Each request is solved independently in its own precision mode.

Public checks performed

These are local development checks; timings are from the shared development core.

  • tools/run_local.py on dev/manifest.json with 3 repeats: 56/56 valid. The largest error is 0.32 of the tolerance.
  • tools/run_local.py on dev_full/manifest.json with 3 repeats: 40/40 valid. The largest error is 0.29 of the tolerance, peak memory is 69 MB, and the total of median times is 3.1–3.3 s. The low-eta cases (n=60k–100k) take 6–35 ms each, mostly reading the input. The largest case (n=75k, nnz=820k, t*||L||=1e5, p10, degree about 1100) takes about 0.75 s.
  • A randomized stress test against dense eigendecomposition: about 940 cases across development versions, 100 of them on the final binary. It covered random, disconnected, signed, potential-shifted, diagonal, path, log-spectrum (n up to 700) and random-geometric/random graphs (n of 3000–5000), with t*||L|| up to 1e5, all precisions, both scenarios, and dense, impulse, zero, tiny and "high-frequency" (L*r) right-hand sides. There were no failures. The worst error was 0.34 of the tolerance, which is the designed bound of the stopping rule; it is reached only for inputs dominated by the null space.
  • Forced fallbacks: a Lanczos interval shrunk by 3%, 10% or 40% is detected by the growth monitor and recomputed correctly. Forced extended precision gives the same answers. run.sh still works with binaries that have no exec bit on a read-only directory (it copies them), and with no binaries at all (it compiles from source). --check fails on a deliberately broken AVX2 kernel.
  • A full-scale synthetic reuse session (16 requests, nnz=820k, t*||L||=1e5, p10, mixed right-hand sides) takes about 12 s against the 240 s limit, at 86 MB peak memory.

Diagnostics go to stderr only when EXPO_VERBOSE is set. The other EXPO_* environment variables are development and testing switches and are unset during evaluation.

Exponential propagation solver (FAMEXP2)

Computes y = exp(-tL) b0 + t*phi1(-tL) b1 for a sparse symmetric PSD L over the FAMEXP2 stdin/stdout protocol (one-shot and 16-request reuse sessions).

Algorithm

  • Augmented Chebyshev series. y is the first block of exp(-tB)[b0; 1] with B = [[L, -b1], [0, 0]], whose spectrum is spec(L) plus 0, i.e. inside [0, lam]. exp(-t x) on [0, lam] is expanded in Chebyshev polynomials (coefficients exp(-rho) I_k(rho), rho = t*lam/2, from Miller's backward recurrence). The scalar block of the augmented iterate is (-1)^k, so every term costs one fused SpMV + vector update (`v_{k+1} = 2(I - aL)v_k - v_{k-1}
  • 2a b1,y += 2 e_{k+1} v_{k+1}`), with no Krylov basis to store.
  • Spectral bound lam. Rigorous Gershgorin and Collatz-Wielandt (x = sqrt|diag|) bounds; for long series a short Lanczos run (35-60 steps, 1% + 2*residual margin), capped by the rigorous bound. If an iterate ever exceeds 1e4 times its theoretical size (lam too small), the request is restarted with the rigorous bound.
  • Adaptive truncation. Stop when the coefficient tail times the observed iterate size, plus the k^2-growth bound of the phi1 part, is below 2% of atol + rtol*max|y| (in practice errors are <= 4% of the tolerance).
  • Small components. If every connected component has <= 24 nodes (e.g. block-diagonal operators) each block is diagonalised once (Jacobi) and every request is evaluated exactly in O(n).
  • Trivial cases. t = 0 or L = 0: y = b0 + t*b1.
  • Performance. C, single thread. Long runs use a SELL-4 copy of L (4 rows per slice, length-sorted in windows of 128 rows, column-major), which removes per-row branch mispredictions and gives 4 independent FMA chains; poorly ordered matrices (e.g. random geometric graphs) are first reordered by reverse Cuthill-McKee. Input is read straight into a 2 MB-page arena that is pre-faulted before READY; pipes are enlarged to 1 MB; the Gershgorin scan runs on rows as their values arrive and the Collatz-Wielandt pass runs while the first right-hand side streams in. Reuse sessions keep lam, coefficients, orderings and buffers across requests.

Files / dependencies

  • expo.c - complete solver (C99, libm only).
  • expo - prebuilt binary: gcc -O3 -march=x86-64-v3 -o expo expo.c -lm.
  • run.sh - starts the prebuilt binary; if it is missing or the CPU lacks AVX2/FMA it recompiles into /tmp with the system gcc before READY. No other dependencies; no build step is required.

Public checks

  • tools/run_local.py on dev/ (56 cases incl. reuse and controls) and dev_full/ (40 full-size cases): all pass, worst error 0.034 of the tolerance.
  • Extra synthetic checks against dense eigendecompositions: random geometric graph at t*||L|| = 1e5 (RCM + SELL + Lanczos path, one-shot and reuse), mixed giant/small components with a potential, power-law hub graph, 3x3 log-spectrum blocks, 1e9-scaled Laplacian, explicit zero matrix, n = 1, and a forced lam underestimate (restart path).
  • Public evaluator (submit --test): all 72 cases valid, public-set score 62.8-63.7 across runs (baseline 50); small cases are quantised by the harness to ~10 ms steps.
  • Stress: n = 120000, nnz ~ 1e6, t*||L|| = 1e5, p10, 16 requests: 18 s wall, ~200 MB peak memory.
