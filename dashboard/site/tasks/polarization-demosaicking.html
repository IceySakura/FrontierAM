偏振马赛克图像重建

计算成像 · 从一张 1024×1024 的偏振马赛克中重建 0°/45°/90°/135° 四幅完整图像，每景 1 秒，RMSE 越小越好。

题目背景

偏振相机在每个像素前放一个微型偏振片，相邻 2×2 像素分别测 4 个偏振方向，所以每个方向只直接测到 1/4 的像素，其余要插值重建（去马赛克）。偏振信息用于识别材质、去除反光、工业检测和三维形状恢复，重建误差会直接放大到偏振度和偏振角的计算里。经典做法是逐方向双线性插值；更先进的方法（如 LEIC、EARI）利用不同方向之间的相关性和边缘信息。

公开题面原文（给模型的版本）

题目名称

从一张偏振马赛克重建四幅强度图

问题描述

相机在每个像素上只测量一个偏振方向的光强。给定一次曝光得到的单通道图像 raw，请估计同一画面在 0°、45°、90°、135° 下的四幅完整图像。滤片从图像左上角开始，按下表每两行、两列重复排列。行列从 0 开始。

偶数列 奇数列
偶数行 90° 45°
奇数行 135° 0°

正式输入是形状为 (1024, 1024) 的 NumPy uint8 数组，读数在 0 至 255 之间。四幅目标图与输入坐标对齐。例如在偶数行、偶数列，输入给出了该位置的 90° 强度，其余三个方向需要估计。

算法目标

用同一个程序处理所有场景，使四幅重建图在完整画面上的强度误差尽可能小。一个像素的四个方向可以有不同亮度。程序可以使用整幅输入，自行决定怎样利用相邻像素以及不同方向的观测。

算法约束

每个场景在独立进程中离线运行，限 1 个逻辑 CPU、单线程、8 GiB 内存、无交换空间。每景墙钟时间上限为 1.000 秒，独立计时。计时从启动该景运行进程前开始，到完整写出结果且进程正常退出为止，包括 Python 启动、模块导入、输入读取、计算及输出写入。容器准备、一次性构建、评测端验分另计。平台提供 Linux ARM64、Python 3.11、NumPy 1.26.4 和 SciPy 1.12.0。

开发时可查阅和复用公开方法。运行时只能使用本景马赛克和通用于各景的源码、参数。禁止使用正式场景的完整参考图或其衍生数据进行训练、调参、识别场景查表或硬编码答案。每景使用干净的工作目录，禁止跨景保存状态。若使用随机算法，统一以环境变量 SEED=1 为起点。

raw 为只读二维数组。返回一个形状为 (4, H, W) 的 NumPy 数组，类型为 float32 或 float64，所有元素均须有限。pred[0] 至 pred[3] 依次对应 0°、45°、90°、135°。输出与输入使用同一强度单位，允许小数。评测方按提交的数值直接评分，超出 0 至 255 的预测也原样计入误差。

评测指标

每景分别对四个方向计算全图均方根误差（RMSE）。若某方向的输出、参考图分别为 $P$、$R$，则该方向的误差为 $\sqrt{\sum_{i,j}(P_{ij}-R_{ij})^2/(HW)}$。图像四边、四角和已观测的像素都计入。每景先对四个方向的 RMSE 取算术平均，再对固定的 32 个场景等权平均，得到整批误差 $E$。每景评一次，$E$ 越低越好，整批只换算一次分数。

0 分对应经典方法的表现，5 分对应现有较先进方法的表现，10 分对应零误差的理论最优。两条参照在固定测试集上的整批误差分别记为 $B$、$H_5$，满足 $B>H_5>0$。项目分满分 10，按下表计算。

整批误差 项目分
$E\ge B$ $0$
$H_5\le E<B$ $5(B-E)/(B-H_5)$
$0\le E<H_5$ $10-5E/H_5$

32 景均须成功。构建失败或任一景出现提交导致的超时、超内存、异常退出、缺失或非法输出，整份计 0 分。由提交导致的失败不重跑。平台故障修复后按原条件恢复。耗时和峰值内存另行记录，同分并列。

评测依据

  • 输入：1024×1024 的 uint8 马赛克，滤片相位固定（偶偶 90°、偶奇 45°、奇偶 135°、奇奇 0°）。
  • 正式集：32 个真实场景（30 景普通照明、2 景偏振照明）。
  • 资源：每景独立进程，单核、8 GiB、墙钟 1.000 秒（含 Python 启动和导入）。
  • 有效性：任一景超时、超内存或输出非法，整份提交记 0 分。
  • 原始指标：每景对 4 个方向分别算全图 RMSE 再平均，32 景等权平均。
  • 换算：设双线性的误差为 \(B\)、镜像 LEIC 为 \(H_5\)。\(E \ge B\) 记 0 分；\(H_5 \le E < B\) 记 \(50(B-E)/(B-H_5)\)；\(E < H_5\) 记 \(100-50E/H_5\)。

模型自己写的说明（提交中的 README.md）

Four-angle polarization demosaicking

solution.py defines reconstruct(raw): given the 2-D uint8 mosaic with the 2×2 tile [90°, 45°] / [135°, 0°] (rows/cols counted from 0), it returns a float32 array of shape (4, H, W) with the 0°, 45°, 90° and 135° images, clipped to [0, 255].

Method

  1. Frequency-multiplexing model. With X = (-1)^col, Y = (-1)^row, every mosaic value is exactly r = L − X·C1 − Y·C2, where L = S0/2, C1 = (S1+S2)/4, C2 = (S1−S2)/4. The polarization signals sit on the (π,0) and (0,π) carriers, and for ideal polarizers the (π,π) band holds only intensity (see step 4). Once C1 and C2 are estimated, L = r + X·C1 + Y·C2 and I0 = L+C1+C2, I45 = L+C1−C2, I90 = L−C1−C2, I135 = L−C1+C2. This reproduces every observed pixel exactly and keeps the full-resolution intensity detail that is in r.
  2. Steered learned filters. C1 and C2 come from the demodulated mosaics −X·r and −Y·r. Each is filtered with five learned 11×11 kernels. Their responses are combined per pixel with weights 1, cosφ, sinφ, cos2φ, sin2φ, where φ = 2θ comes from a smoothed structure tensor of same-phase gradients. Low-energy regions get small weights through a threshold. The kernels were fitted offline by least squares on synthetic polarization scenes built from SciPy's bundled face/ascent test images (with random piecewise-smooth DoLP/AoP fields and sensor noise) and on generated scenes like the public examples. Flips and transposes were used for augmentation. No evaluation data was used. The coefficients are embedded in solution.py (kernels.npy is the same array).
  3. Edge-aware ratio-domain blend. Within a surface the polarization ratio C/L varies more slowly than C itself. Each chroma becomes 0.4·C + 0.6·L·smooth(w·C·L) / (smooth(w·L²) + 1), using a separable [1,4,6,4,1] window. The weight is w = 1/(1 + g²/36), where g is the same-phase gradient across the carrier direction (horizontal for C1, vertical for C2). This down-weights the pixels next to edges, which is where intensity leaks into the chroma estimate.
  4. (π,π) component. D = (I0+I90−I45−I135)/4 is zero for ideal polarizers. It can still absorb smooth gain differences between the angle channels. It is estimated as a strongly smoothed ratio D/L (à-trous [1,4,6,4,1] passes with dilations 1, 2, 4, 8) of the (π,π)-demodulated mosaic, and is included in the output. The observed pixels are still reproduced exactly.
  5. Mirror padding keeps the 2×2 phase at the borders. The filters are applied with numpy.fft on a fast transform size (1040 for 1024² inputs). Inputs smaller than 12×12 use a nearest-sample fallback.

Dependencies and running

  • Python 3.11 and NumPy only. There is no SciPy import at run time, which keeps start-up fast. Nothing needs compiling, so there is no build.sh.
  • Files: solution.py (self-contained: the learned coefficients, shape (2, 5, 11, 11), are embedded in it as base64). kernels.npy holds the same coefficients for reference only.
  • Usage: from solution import reconstruct; pred = reconstruct(raw), or python3 public-dev/check.py submission/solution.py.
  • The method is deterministic, single-threaded and stateless. A full 1024×1024 scene runs end to end (interpreter start, imports, compute) in about 0.45 s on the development machine.

Third-party sources

The code is original. The modulation analysis follows the standard frequency-domain view of CFA/DoFP demosaicking (Alleysson et al.; Dubois). Steering learned filters by local orientation is in the spirit of RAISR (Romano et al.). The ratio smoothing is related to residual and guided interpolation. The training images are the public SciPy sample images scipy.misc.face and scipy.misc.ascent.

观察与说明

  • 题目给 agent 的开发材料里只有两组用公式合成的样例，没有真实场景。我们找到并实测了 Wen 等 2019 的公开数据集（105 景，裁成 1024×1024 后耗时与正式输入一致，LEIC 在 100/105 景上优于双线性），作为公开反馈集，待出题人确认。
  • 测试场景经过按参照表现的筛选（去掉了双线性比 LEIC 更准的场景），这会放大两条参照之间的差距，已请出题人确认。
  • 评分时第一个运行的景总是比其余各景慢 0.14–0.5 秒，在 1 秒上限下可能导致整份提交失败；原因在排查中。
